## 1. 死归还原链

### 1.1 死归之后手牌点不动，只能结束回合（0.2.6 → 0.2.9）

- **症状**：死归演出结束、轮到自己，手牌是亮的但点不动，直到回合结束才恢复。
- **第一次修错**：0.2.8 在刷新手牌 UI 前加了 `if (manager.IsEnemyTurnStarted) return;`。日志直接打出
  `hand ui refresh skipped: enemy turn`，问题没解。
- **根因（IL 核实）**：`IsEnemyTurnStarted` 只有一个写入方（`CombatManager.StartTurn`），**没有任何读取方**——
  它是个纯记录用的残留标记，死归发生在敌方回合里，这个值就是 true，拿它当闸门等于永远跳过。
- **修法**：`Rewind/Spike.cs` `RefreshHandUi()`（约 542 行）改按 `state.CurrentSide` 判断；
  玩家侧还挂着 `PlayerActionsDisabled` 就强制放开；再 `CancelAllCardPlay()` → `UpdateHandDisabledState()` →
  延后一帧 `OnCombatStateChanged()` + `RefreshLayout()`。
- **验证**：日志 `force player actions enabled`、`hand ui refreshed`。

### 1.2 用掉药水后再死归，报 NullReference（0.2.7）

- **症状**：喝过药水、然后死归 → 日志 `discard potion failed: NullReferenceException`。
- **根因**：还原快照时无条件对快照里的每瓶药水调 `PotionCmd.Discard`，已经用掉的那瓶 `Owner == null`、
  已从状态移除，`Discard` 内部解引用就炸。
- **修法**：`Rewind/BattleSnapshot.cs`（约 427 行）判 `potion.HasBeenRemovedFromState || potion.Owner == null` 就跳过。
- **验证**：日志 `potion already gone, skip discard`。

### 1.3 被击杀那一刻血条显示 1 血（0.2.10 → 0.2.11）

- **症状**：死归动画全程血条写着 1，看起来像没打死。
- **根因**：死归把血量还原成 1（设计如此），UI 的 `NHealthBar.RefreshValues()` 会按真实血量重写数字，
  把「0 血」的伪装盖掉；另外遮罩撤得太早，动画还没播完就恢复了。
- **修法**：`UI/RewindHealthMask.cs` 加 `_masked` 记账，`RefreshBar()` 在遮罩期间直接 return（约 128 行）；
  `UI/RewindAnimation.cs` 把撤遮罩挪到黑幕淡出（`RevealFromBlackout(0.25)`）之后再等 0.35s。
- **验证**：日志 `health bar refresh suppressed (mask active)`。

## 2. 卡牌规则

### 2.1 魔女瘴气回合结束被丢弃（0.2.12 → 0.2.13）

- **症状**：写了 `[保留]`，但每回合结束瘴气还是从手牌消失，玩家失去的效果也乱。
- **第一次修错**：只拦 `AddTurnEndCardToPlayPileWithDelay`。日志显示拦住了，牌还是没了。
- **根因（IL 核实）**：`CardModel.HasTurnEndInHandEffect` 为真时，引擎在 `DoTurnEnd` 里分三步搬牌：
  ① 收进 `DoTurnEndCards` → ② `AddTurnEndCardToPlayPileWithDelay`（搬进出牌堆）→ ③ 结算 →
  ④ `TweenTurnEndCardToResultPile`（再搬去结算堆）。第三步才是真正让牌离开手牌的那一下，只挡 ② 没用。
  `[保留]` 拦的是「弃手牌」流程，跟这条通道无关。
- **修法**：删掉卡上的 `HasTurnEndInHandEffect` / `OnTurnEndInHand`（`Cards/CurseWitchMiasma.cs` 现在只有
  `[Retain]` + `[Unplayable]`），扣血改由初始遗物在 `BeforeSideTurnEnd` 自己算：
  `Rewind/PrideFactorSpike.cs`（约 78 行）数手牌里的瘴气，每张造成 1 点不可格挡伤害。
- **验证**：日志 `miasma end-of-turn damage: N card(s)`。

### 2.2 腐蚀牌能被再次打出 / 从消耗堆取回（0.2.24 → 0.2.25）

- **症状**：腐蚀牌一场只能打一次的规则存在漏洞——自动打出（幻景等）和「从消耗堆取牌」的路径不查 `IsPlayable`。
- **根因（IL 核实）**：`CardCmd.AutoPlay` 只问 `ShouldPlay` 钩子，**不问** `IsPlayable`；
  另有一条 `CardPileCmd.Add` 把牌从 Exhaust 搬回手牌的通道。
- **修法**（三层，缺一层就有缝）：
  | 层 | 位置 | 挡什么 |
  |---|---|---|
  | `IsPlayable` | `Cards/SubaruCard.cs`（override 在 204 行，腐蚀判据在 209 行） | 手动出牌 |
  | `ShouldPlay` | 同文件（约 225 行） | 自动打出 |
  | `CardPileCmd.Add` 拦截 + `CardSelectCmd.FromCombatPile` 过滤 | `Patches/CorrodedExhaustGuard.cs` | 从消耗堆取回 / 选牌界面里出现 |
- **判据**：一律用**实例引用** `CorrodedCards.IsUsed(card)`，不能按原型判——按原型会把同名的第二张合法副本一起吞掉。
- **验证**：`exhaust selection: corroded cards filtered out`、`exhaust retrieval blocked (corroded card)`。
- **注**：现版本没有任何原版卡会从消耗堆把牌拿回手牌（`Exhume` 在官方补丁说明里已标 Deprecated，
  放逐牌堆的消费者只有幻景/刀刃陷阱/轰击系），所以这两层目前是**兜底**，不是修可见 bug。

## 4. 工具链坑

### 4.1 构建 / 部署

- **MegaDot 的 `exit -1` 是假失败**：`dotnet publish` 结尾常报
  `MSB3073 ... MegaDot_v4.5.1... --export-pack ... 已退出，代码为 -1`，还带几条 `Cannot save editor_settings`。
  只要日志里出现过 `[ DONE ] savepack`、且 `dist\Subaru\Subaru.pck` 的时间戳是新的，就是成功。**别看退出码**。
- 构建前必须删 `dist\Subaru\Subaru.pck`，否则可能拿到上一次的包。
- 环境变量：`TEMP/TMP`、`NUGET_PACKAGES`、`NUGET_HTTP_CACHE_PATH` 指到工作区（`.tmp` / `.nuget`）即可，
  `_tools` 下同名目录也能用，两套都验证过。
- `deploy_mod.py` 在游戏运行时必然 `PermissionError [WinError 32]`——先关游戏。

### 4.2 反编译验证（IlDump / apilist）

- `_tools\IlDump\bin\Debug\net9.0\IlDump.exe <dll> 'Type::Method'`、`--calls <member>`、`--fields <type>`，
  结果写 `il_out.txt` / `callers_out.txt` / `fields_out.txt`。
- `_tools\apilist\bin\Release\net9.0\apilist.exe <dll> type|member <substr>` 查 API 与字符串。
- **教训**：本档案里 1.1 和 2.1 都是先凭直觉改了一版、失败后才去读 IL。凡是「引擎会不会自己动这张牌 /
  会不会自己刷这个 UI」这类问题，先 `--calls` 查调用方，比改代码试快得多。
- 两个被 IL 推翻的想当然：
  1. `IsEnemyTurnStarted` 有读者 → **零读取方**，纯记录。
  2. `FlushPlayerHand` 会走 `CardCmd.Discard`（所以补丁能拦）→ 它走的是 `CardPileCmd.Add(..., PileType.Discard)`，
     `NoDiscardPatch` 根本收不到。
- `CombatManager.StartTurn` 的顺序：先 `PlayerActionsDisabled = false`，**然后**才 `SetupPlayerTurn`（能量 → 抽牌 →
  `AfterPlayerTurnStart` 三段钩子）。所以「回合开始」的钩子里不要再假设动作是锁着的。

### 4.3 卡牌表同步脚本（`_tools\sync_cardtable.py`）

解析源码表格时踩到的五个坑，改脚本时别再踩：

1. **类块会带下一张牌的文档注释**：用「从 `class X` 到下一个 `class`」切片，尾部 `/// <summary>` 属于下一张牌。
   不先剥注释，`HasEnergyCostX` 之类的字符串会串到隔壁（曾把剑鬼的费用判成 X）。
2. **升级才给的关键词不能写进「关键词」列**：幼女使者、首席骑士、强子契约（Emt/Emm）等，`[固有]`/`[保留]`
   是 `OnUpgrade()` 里 `AddKeyword` 加的，关键词列只写基础关键词，升级那一列写「获得[保留]」。
3. **两种变量写法都要认**：`DynamicVars.Damage.UpgradeValueBy(2m)` 和 `DynamicVars["Hits"].UpgradeValueBy(1m)`。
4. **费用 `-1` 有两种含义**：不可打出的诅咒（魔女瘴气）和 X 费。判据是类体里有没有 `HasEnergyCostX`，
   不是看 `-1`。
5. 数据源用 `localization\zhs\cards.json`，不要用 eng——表是给中文看的，名字必须跟游戏内一致。

脚本只改数值格，样式、「来源 / 流派 / 备注」和行序都保留；旧表自动备份成 `docs\卡牌表.bak4.xlsx`，
并逐格打印改了哪些。

### 4.4 工坊上传

- **退出码 1 也是成功**：`ModUploader.exe upload -w .` 结尾常以 exit 1 收场，判据是日志里的
  `Successfully uploaded '' to the workshop with id 3840131390!`。
- **再做一道独立核对**：Steam Web API `ISteamRemoteStorage/GetPublishedFileDetails`（POST，`publishedfileids[0]`），
  看 `time_updated` 是不是刚才、`file_size` 跟上传日志里的总字节一致。
- 上传器**不发页面简介**（`workshop.json` 里的 `title/description` 已删空，避免覆盖手改内容）；
  简介从 `release\workshop\Subaru\发布文案.md` 手动粘贴。
- 文案规则见笔记「Steam 工坊文案规范」：现在的口径是 **changeNote 只传英文，中文版在对话里交给用户手动上传**；
  中文里的卡名/能力名必须照抄 `localization\zhs\*` 的 `title`（0.2.26 出过「愤怒司教·洗魂」写成「天狼星：魂洗」的事故）。

## 7. 死归魔女素材池（0.2.27–0.2.31）

一条素材 = 一张黑幕剪影图 + 一段语音；死归演出时等概率抽（洗牌袋，不连抽同一张）。
代码在 `UI/RewindWitchPool.cs`（池 + 掷骰）、`UI/RewindVisuals.cs`（黑幕 / 视频）、
`UI/RewindAnimation.cs`（编排）、`Audio/WitchFaceSfx.cs`（语音，按路径缓存并返回长度）。

| 素材 | 图 | 语音 | 黑幕停留 |
|---|---|---|---|
| 1 | `rewind_face.png` | `witch_face.mp3` | 1.484 s |
| 2 | `rewind_face2.png` | 同上 | 1.484 s |
| 3 | `rewind_face3.png` | 同上 | 1.484 s |
| 4 | `rewind_face4.png` | `witch_face4.mp3`（源音量 ×4） | 1.849 s |
| 5 | —— 视频 `video/rewind_witch5.ogv` | 视频自带音轨 | 4.267 s |

停留时长不再写死：`语音长度 + 0.1`（`FaceHoldPadding`），加长语音不会被淡出掐尾。

### 7.1 素材 5 的两个坑

**① `.ogv` 没有导入器。** 这个引擎（MegaDot 4.5.1）的编辑器**不认 Theora**：`--import` 只给
`.ogv` 生成一个 `.uid`，不生成 `.import` / `.ogvstr`，手写 `.import` 也没用。
做法是把它当**原始文件**打进 pck——`export_presets.cfg` 的 `include_filter` 必须含
`Subaru/video/*.ogv`——运行时 `new VideoStreamTheora { File = "res://..." }` 直接按路径读，
**不能 `GD.Load`**。运行时确实有解码器（0.2.30 实机确认能播）。
拿不到视频就返回 0，调用方回落到图片池，不会黑屏卡住。

**② 癫狂预测的判据错了一版。** 素材 5 只在「这次死归会触发癫狂」时参与 50/50，而癫狂判定在
还原之后才做，所以演出时要预测。0.2.29 数的是**存档点手牌**里的瘴气——存档点是开战那一刻，
永远是 0 张，日志恒为 `saved=0 pending=1 pride=3 => False`，视频一次都抽不到。
正确算法是数**当前手里**的瘴气 + `_pendingCurses`：瘴气是跨回档保留的牌
（`RestorePile` 保留 `IsPersistentCard`），还原后手里还是这些。
判据必须和 `TryTriggerMadness` 保持一致：`hand + pending >= pride && pride > 0 && 无癫狂`。
