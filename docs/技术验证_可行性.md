## 二、逐条说明

### 1. 无视防御的伤害

游戏把「伤害属性」做成了一组标记：

```csharp
[Flags] enum ValueProp { Unblockable, Unpowered, Move, SkipHurtAnim }
```

`AttackCommand.DamageProps` 的类型就是 `ValueProp`（`sig.txt:374/417`）。
所以「最优之友」这种卡直接加标记：

```csharp
await DamageCmd.Attack(9)
    .FromCard(this, cardPlay)
    .Targeting(target)
    .WithDamageProps(ValueProp.Unblockable)   // 无视格挡
    .Execute(choiceContext);
```

> 需在原型里确认 `WithDamageProps` 的确切方法名（同一命名空间内已有 `Unpowered()` 便捷方法，风格一致）。

### 2. 斩杀

```csharp
Task Kill(Creature, bool);
Task Kill(IReadOnlyCollection<Creature>, bool);
```

「阿尔·纱幕」的群体斩杀直接：

```csharp
var targets = combatState.HittableEnemies.Where(c => c.CurrentHp < threshold);
await CreatureCmd.Kill(targets, true);
```

> 第二个参数大概是「是否算作击杀」，原型里确认。

### 3. 按稀有度产生效果

`CardModel` 暴露 `Rarity`，底层是 `CardRarity` 枚举（`sig.txt` 里 `CardRarity` 存在，`CardRarityExtensions` 有一组扩展方法）。
「忧郁魔女」：

```csharp
switch (card.Rarity)
{
    case CardRarity.Common: ...
    case CardRarity.Uncommon: ...
    case CardRarity.Rare: ...
}
```

### 4. 死亡拦截 —— 死归的触发点

官方 `LizardTail`（蜥蜴尾）就是「免死一次」的遗物，实现只有两个方法：

```csharp
bool ShouldDieLate(Creature creature);          // 返回 false 阻止死亡
Task AfterPreventingDeath(Creature creature);   // 免死后的收尾
```

`Hook` 里对应 `ShouldDie / ShouldDieLate / AfterPreventingDeath / AfterDeath`（`sig.txt:232` 等）。
**死归直接照这个范式写**，可以在 `AfterPreventingDeath` 里做回档 + 塞诅咒 + 加遗香。

### 5. 回档 —— 唯一真正的难点

游戏**没有**「战斗状态快照」API。唯一叫 Snapshot 的是 `AutoSlayLog.StateSnapshot`，那是自动战斗的日志，不能用。

要自己做快照，需要覆盖：

| 对象 | 字段 | 恢复手段 |
|---|---|---|
| 玩家 | HP、格挡、能量、能力层数 | 直接赋值 / `PowerCmd` |
| 手牌 | 牌列表与顺序 | `CardPileCmd` 增删 |
| 抽牌堆 / 弃牌堆 / 消耗堆 | 牌列表与顺序 | 同上 |
| 敌人 | HP、格挡、能力、意图 | 赋值 / `PowerCmd` / 意图重设 |

**建议分两级做：**

- **MVP（低风险）**：只快照/恢复**玩家侧**（HP、格挡、能量、手牌、三个牌堆）。敌人保持当前状态。
  → 玩起来像「回到本回合开始重打一遍，但敌人已经挨的伤害保留」，机制成立，实现量小。
- **完整版（高风险）**：连敌人 HP/能力/意图一起回滚。需要在 `AfterSideTurnStart` 抓快照，并处理动画/队列。

> 这条决定整个角色的实现成本，建议先用 MVP 验证手感。

### 6. 癫狂「每回合最多打出 3 张」

```csharp
int ModifyCardPlayCount(ICombatState, CardModel, int currentCount, Creature, out List<AbstractModel>)
```

在癫狂状态下把计数钳到 3 即可。注意 `AutoPlay` 是否也走这个计数器，需要在原型里确认。

### 7. 贝蒂在场时费用为 0

```csharp
decimal ModifyEnergyCostInCombat(ICombatState, CardModel, decimal cost)
```

检测「贝蒂」Power 是否存在，存在则返回 0。

### 8. 往手牌塞诅咒

```csharp
CombatState.CreateCard(...)      // 生成一张牌实例
CardPileCmd.Add(...)             // 放进指定牌堆（含手牌）
```

死归时：`CreateCard<CurseWitchMiasma>()` → 加到 Hand。

### 9. 魔女瘴气的消耗限制

「不能被丢弃 / 不能被遗物消耗 / 只能被指定牌消耗」这套要三层拦截：

1. 牌本身：`Unplayable` + 自定义 `Retain`（已有）
2. 丢弃拦截：覆写牌的可丢弃判定（原型确认 `CardModel` 上的虚方法名）
3. 消耗拦截：在 `CardCmd.Exhaust` 的调用点做判断——凡是「消耗其他牌」的来源，检查目标是不是魔女瘴气，是就跳过

> 这块是「规则约束」而不是「新机制」，实现上是散点式防御，工作量大但不难。

### 10. 关键词与状态

- **关键词**（权能 N、腐蚀、幼女使者）：BaseLib 有自定义关键词/枚举支持（`CustomEnums`），卡面显示走关键词 tooltip
- **状态**（傲慢、癫狂、魔女遗香、浮空、贝蒂）：用自定义 `Power` 承载层数，BaseLib 有 `CustomPowerModel`

### 11. 存档点（迷失）

用 `SavedProperty` 记录「存档点回合数」，`AfterPlayerTurnStart` 时更新；死归时读它决定回到哪一回合。

### 12. 贝蒂 / 召唤

游戏内已有完整召唤体系（Necrobinder 的 Osty）：

```csharp
OstyCmd.Summon(...)
PlayerCmd.AddPet(...)
Hook.AfterSummon / AfterOstyRevived
```

「贝蒂」可以做成 Pet（有独立血条）或纯 Power（不承伤）。按你的设定「贝蒂是一种状态，不承伤」，**建议做成 Power，不做 Pet**，省掉一整套 UI 与目标逻辑。

## 三、风险与缓解

| 风险 | 说明 | 缓解 |
|---|---|---|
| R1 回档不完整 | 敌人状态、意图难以精确还原 | 先做 MVP（只回玩家侧），手感够用就不做完整版 |
| R2 死亡回调递归 | 回档时再次触发死亡判定 | `ShouldDie` 内加重入锁 |
| R3 联机不同步 | 回档是单机语义 | 联机下禁用死归，或标记 `affects_gameplay` |
| R4 打出上限误伤 | `AutoPlay` 也被计数 | 原型里验证并放行自动打出 |
| R5 存档兼容 | 存档点写进存档 | 用 `SavedProperty`，随版本迁移 |

## 五、结论

- 除**回档**外，所有需求都有官方原生 API 或清晰范式，风险可控
- 回档建议先做「只回玩家侧」的 MVP
- 下一步就是写这 6 个实验类并编译

### 实测到的正确签名（照抄即可）

`csharp
// 无视格挡
var cmd = DamageCmd.Attack(9).FromCard(this).Targeting(target);
cmd.DamageProps = ValueProp.Unblockable;

// 斩杀
await CreatureCmd.Kill(targets, true);

// 死亡拦截（AbstractModel 虚方法）
public override bool ShouldDieLate(Creature creature);
public override Task AfterPreventingDeath(Creature creature);

// 每回合打出上限
public override int ModifyCardPlayCount(CardModel card, Creature? target, int playCount);

// 费用修改（注意是 out，不是 ref）
public override bool TryModifyEnergyCostInCombat(CardModel card, decimal cost, out decimal newCost);
`

### 编译期纠正的两个坑

1. AttackCommand.FromCard 只接受 **1 个参数**（卡牌本身），不是 (card, play)
2. 费用钩子是 TryModifyEnergyCostInCombat(..., out decimal newCost)，**out 而不是 
ef**
