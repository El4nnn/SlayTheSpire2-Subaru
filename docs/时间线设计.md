# 昴的时间线 · 轮回记录

> 📌 **draft** ｜ 最后核对：2026-11-23 ｜ 方案 B 未实装

> 现状：只有 1 个节点（`SUBARU_EPOCH_CALL`，已能在 β 里显示）。
> 本文是把这一列扩成**一套**的设计稿：一条独立的列、6 个节点、以「死归」为轴。

---

## 0. 一句话

别人一条编年史，昴一条**被反复改写的记录**。

原版时间线是「五个时代 × 若干列」，节点写的是"历史上发生过什么"。
昴的设定里，同一段时间被重演了很多次——所以他的列不写"后来发生了什么"，
只写"**同一格，第几次改写**"。

---

## 1. 为什么值得这么做（它同时解决三件事）

| 现在的问题 | 这套时间线怎么解 |
|---|---|
| 新角色硬插进原版五时代，位置说不通 | 自成一列，命名就是"轮回记录"，设定上本来就是个异常 |
| 80 张牌开局全开：第一局信息过载，前期也偏超模 | 按周目放牌，开局只开 24 张（含初始牌组），橙紫卡留到后面 |
| 打完一局就没有下一个目标 | 进阶揭示、傲慢因子+、先古 2 张全部挂到后段节点 |

顺带一个隐性收益：**死归的代价和回报有了叙事解释**——每推进一个节点，就等于"又死了一轮"。

---

## 2. 轨道怎么排

- **列**：接在 `SUBARU_EPOCH_CALL` 所在列**之后**新开一列
  `ModEpochAutoTimelineSlotAfterEpochColumn<SubaruLoop1Epoch, SubaruCallEpoch>()`，
  后续节点用 `ModEpochAutoTimelineSlotInEpochColumn<T, SubaruLoop1Epoch>()` 叠进同一列。
- **回退方案**：如果"新开列"在 β 上排版错位，改成
  `ModEpochAutoTimelineSlotInColumn<T>(EpochEra.Invitation4)`，让 RitsuLib 自己抢最后一个时代列的空位。
- **每个节点需要**：3 个本地化键（`title` / `description` / `unlockInfo`）+ 2 张立绘（big / packed）。
  首版 6 个节点可以共用同一张昴的裁切图，美术后补。

> ⚠ 命名陷阱：`StoryKey => "SUBARU"` 在日志里被格式化成 `S_UB_AR_U`。
> 新节点 ID 一律用**单词间下划线**（`SUBARU_LOOP_1`），别写成 `SUBARULOOP1` 这种连写。

## 3. 七个节点

| # | Epoch ID | 标题 | 解锁条件（RitsuLib 内置 rule） | 解锁内容 |
|---|---|---|---|---|
| 0 | `SUBARU_EPOCH_CALL` | 异世界召唤（已有） | 故障机器人完成一局 | 角色 |
| 1 | `SUBARU_LOOP_1` | 第 1 次 · 赃物库 | 以昴完成一局 `UnlockEpochAfterRunAs` | 王都包 8 张 |
| 2 | `SUBARU_LOOP_2` | 第 2 次 · 罗兹瓦尔宅邸 | 以昴累计击败 3 个精英 `UnlockEpochAfterEliteVictories<Subaru,…>(3)` | 宅邸包 7 张 + 遗物「傲慢因子」 |
| 3 | `SUBARU_LOOP_3` | 第 3 次 · 白鲸 | 以昴累计击败 2 个首领 `UnlockEpochAfterBossVictories<Subaru,…>(2)` | 白鲸包 8 张 |
| 4 | `SUBARU_LOOP_4` | 第 4 次 · 圣域试炼 | 以昴累计击败 5 个首领 | 魔女包 15 张 |
| 5 | `SUBARU_LOOP_5` | 第 5 次 · 水门都市 | 以昴通关一局 `UnlockEpochAfterWinAs` | 水门包 13 张 + 遗物「傲慢因子+」+ **进阶界面揭示** `RevealAscensionAfterEpoch` |
| 6 | `SUBARU_ARCHIVE` | 记录之外 | 以昴进阶 5 获胜 `UnlockEpochAfterAscensionWin<Subaru,…>(5)` | 记录之外包 3 张 + 先古 2 张 |

卡牌怎么分到这些包里，见 §5。

七个节点里，0 是前置、1–5 是主线、6 是终局。

**为什么条件用的是精英/首领/通关，而不是"死够多少次"**：
RitsuLib 内置的局后判定只有 跑局 / 通关 / 局数 / 精英胜 / 首领胜 / 进阶胜 六种，没有死归维度。
死归维度的做法见 §4——技术上可行，但要多接一层存档，先不进首版。

## 4. 「死归次数」门（v2，可选）

做得到，但要两步：

1. **存**：`RunSavedDataStore.Register<int>("subaru_rewind", …)`，每次死归 +1；
2. **读**：`ModUnlockRegistry.RegisterPostRunRule(PostRunEpochUnlockRule.Create(id, 说明, ctx => ctx.CharacterId == 昴 && 读(ctx.Run) >= N))`

风险点只有一个：局后能不能从 `ctx.Run`（`SerializableRun`）里拿到我们写进去的 run 数据，需要实测。

**推荐的用法是"第二把钥匙"，不是替换主线**：

> `SUBARU_ARCHIVE` 的解锁条件 = 进阶 5 获胜 **或** 单局死归 ≥ 20 次。

"赢不了就死够二十次"——这是整个角色最贴题的一个彩蛋，两条路都通向同一个节点。

## 5. 卡牌闸门（方案 B，已定）

现状 `SubaruCardPool` 是 `SeenByDefault = true` + `FilterThroughEpochs` 直接放行 → 80 张全开。
方案 B = 按周目放卡。**本节的分配表就是最终方案，照它实现即可。**

### 5.1 三条切分原则

1. **常开 = 昴自己的能力 + 契约·贝蒂这条线 + 没有归属的工具牌。**
   开局就能解释"我为什么有这张"。
2. **每包 = 那个篇章里认识的人。** 牌名就是人名，解锁节点就是登场节点。

### 5.5 三条必查的坑

1. **初始牌组那 5 种牌绝不能进任何闸门**（打击 / 防御 / 契约·贝蒂 / 纱幕 / 基尔提之鞭）。
   它们里有一个稀有、一个罕见，按稀有度切会误伤——这也是上表按"人名"切而不是按稀有度切的原因。
2. `FilterThroughEpochs` 的放行 override 只管百科显示，奖励池由 RitsuLib 的 `CardUnlockFilterPatch` 管
   ——推断如此，但要实测一次，别假设。
3. **老存档**：闸门只筛"生成 / 奖励"，已抓到的牌应该不受影响；仍需用旧存档验一遍，确认不吞牌。

### 5.6 调它的余地

第一局池子只有 24 张，是刻意做小的：第一局重点是学会死归，不是构筑。
如果实测觉得太单调，把王都包里的 **硬撑 / 跑酷 / 首席骑士 / 艾米莉亚的祝福** 四张提到常开即可，一行改动。

## 6. 六段文本（可直接用）

**第 1 次 · 赃物库**
> 第一次死的时候，我甚至没反应过来那是死。
> 肚子被切开，血是热的，视野是冷的。
> 然后我又站在了那条街上——怀表停在同一个时刻。
> 如果重来一次是唯一的武器，那我就再走一遍。

**第 2 次 · 罗兹瓦尔宅邸**
> 这次我记住了每扇门的位置，记住了谁在什么时候露出什么表情。
> 可蕾姆看我的眼神，还是像在看一个骗子。
> 我死得比上一次更久，也弄明白了：这不是运气，是代价。

**第 3 次 · 白鲸**
> 雾里有东西在动。死了七次之后，我才听懂那声音是什么。
> 威尔海姆先生的剑，库珥修大人的指挥，还有我——一个只会记住失败的人。
> 这一次，我提前知道了结局。

**第 4 次 · 圣域试炼**
> 白色的房间里，她笑着问我要不要喝杯茶。
> 「你已经死过多少次了？」
> 我数不清。但我记得每一次为什么死。
> 从这杯茶开始，我不再只是重来——我开始选择。

**第 5 次 · 水门都市**
> 他们把那叫做大罪司教。
> 我把它叫做：必须活着走过去的又一天。
> 城市的钟声响了，我知道谁会先倒下。
> 这一次，我要让那个名字不上名单。

**记录之外**
> 所有的重来都用完了，故事却没有结束。
> 原来时间线也会记住一个人——
> 不是因为他赢了，是因为他从来没有停下来。

`unlockInfo` 沿用现有格式（未揭示显示条件，已揭示显示"已经…"）：

```
未解锁：以[gold]菜月昴[/gold]累计击败 3 个精英来揭示这个历史节点。
已解锁：已经以[gold]菜月昴[/gold]累计击败 3 个精英。
```

## 7. 代码骨架

```csharp
public sealed class SubaruLoop_1 : ModEpochTemplate { public override string Id => "SUBARU_LOOP_1"; }
// … Loop_2 … Loop_5、SubaruArchive 同理

ModContentPackBuilder.For("Subaru")
    .Story<SubaruStory>()

    .Epoch<SubaruCallEpoch>()
    .ModEpochTimelineSlot<SubaruCallEpoch>(EpochEra.Flourish0, 900)
    .UnlockEpochAfterRunAs<Defect, SubaruCallEpoch>()

    .Epoch<SubaruLoop_1>()
    .ModEpochAutoTimelineSlotAfterEpochColumn<SubaruLoop_1, SubaruCallEpoch>()   // 泛型顺序需编译验证
    .UnlockEpochAfterRunAs<Character.Subaru, SubaruLoop_1>()
    .EpochCards<SubaruLoop_1>(typeof(Elsa), typeof(SwordSaintFriend) /* … */)
    .BindCardUnlockEpoch<SubaruLoop_1>()

    // … Loop_2 起：ModEpochAutoTimelineSlotInEpochColumn<T, SubaruLoop_1>()

    .Apply();
```

编译验证点：`ModEpochAutoTimelineSlotAfterEpochColumn<TEpoch, TReferenceEpoch>` 的两个泛型**哪个在前**
文档没写，写反了会挂错列——第一次编译后进游戏看顺序，10 秒能确认。

## 8. 落地顺序

1. 加 5 个 epoch 类 + 27 个本地化键（文本见 §6）→ 编译 → 进游戏看列、顺序、遮罩。
2. 挂解锁条件（先不加卡牌闸门）→ 打一局确认节点会亮；打 3 个精英确认第 2 个会亮。
3. 加 `EpochCards` + `BindCardUnlockEpoch` → 验证奖励池、商店、百科。
4. 老存档回归：确认不吞牌。
5. 立绘 + 时代轴图标。
6. `docs\卡牌表.xlsx` 加一列「解锁节点」。

## 10. 明确不做

- **不做多人**（已定）。
- **不拿"打到第几层"当条件**：epoch 是局后结算，跟层数无关，硬接会和"死亡即重开"打架。
- **不用时间线调难度**：难度该调数值就调数值，节点只负责"开内容"和"讲事"。
