# 昴 · 动画制作方案 v2（逐帧 + 骨架混合）

> 📌 **active** ｜ 最后核对：2026-11-23 ｜ 现行动画方向

> 2026-11-19 设计稿。替换 `docs/角色形象与动画方案.md`（v1 是 18 骨分件，实际没落地）与当前
> 单骨翻页实现（1 骨 1 槽、229 帧挤在一张 4096² 页面）。
>
> 目标：**逐帧绘制的人物表演 + 骨架化的二级运动 + 独立骨架的华丽特效**，三者叠在一个合成里。

---

## 0. 硬约束（先钉死，设计必须绕着它走）

| 约束 | 值 | 来源 |
|---|---|---|
| 单个骨架只能有 **1 页图集** | 多页 = 第 1 页起画不出来 + 上一帧残影 | `docs/角色动画_图集约束.md`（实测 4 种结构） |
| 单页上限 | 4096 × 4096，BPTC，**mipmaps 必须关** | 同上（RitsuLib 会把 2D 过滤设成 linear_mipmap，开 mip 就采到邻居） |
| 播放帧率 | 30 fps | 现有动画按 1/30 s 采样 |
| Spine 版本 | spine-godot 4.2（MegaDot 4.5.1 导出） | 构建环境 |
| 显存参考 | 4096² 一页 ≈ **16.8 MB**；2048² 一页 ≈ **4.2 MB** | 现有 atlas 实测 |
| pck 体积 | 当前 116 MB，动画部分约 30 MB | 现有包 |

**"单页"是按骨架算的，不按角色算。** 所以破解方式是**拆成多个骨架**，各自一页 ——
现有 `subaru_fx`（施法特效）本来就是这么做的，只是只有 1 骨 1 槽 `cast` 一段。

## 1. 总体分层

```
[子节点顺序 = 绘制顺序，后画的盖前面]

subaru.tscn
└─ Visuals                     SpineSprite  subaru_body      页面 4096²  ← 逐帧主体
   ├─ Rig                      SpineSprite  subaru_rig       页面 2048²  ← 分件骨架（二级运动）
   ├─ SpellVfx                 SpineSprite  subaru_fx_cast   页面 2048²  ← 施法特效（加色）
   ├─ EnvVfx                   SpineSprite  subaru_fx_env    页面 2048²  ← 地面/范围/死归特效（加色）
   └─ ScreenFx                 ColorRect + shader                          ← 全屏闪白/畸变/波纹
```

### 各层职责（关键：谁动什么）

| 层 | 技术 | 负责 | 不负责 |
|---|---|---|---|
| `subaru_body` | 1 骨 + 帧翻页（沿用现有写法） | 身体姿态、表情、衣褶的大形状、动作关键姿态 | 头发飘动、衣角摆动（那是 rig 层） |
| `subaru_rig` | 13 骨分件骨架 | 后发、前发、外套下摆×2、上臂×2、前臂×2、腿×4 的**二级运动** | 换表情、换姿势（那是 body 层帧的事） |
| `subaru_fx_cast` | 骨架 + 帧翻页 + 加色混合 | 手心魔法球、蓄力环、剑光 | 全屏效果 |
| `subaru_fx_env` | 骨架 + 帧翻页 + 加色 | 地面法阵、冲击波、死归时钟波纹 | 角色身上特效 |
| `ScreenFx` | shader | 闪白、径向模糊、色彩分级、屏幕抖动 | 有形状的东西 |

### 为什么这么拆

1. **单页上限是物理限制**：逐帧最多能塞 ~120 帧（300×400 一帧算），做不出"华丽"。
   骨架层的头发/衣摆不需要逐帧画，几根骨头几组关键帧就够，几乎不占页。
2. **特效要独立**：加色混合（additive）必须单独节点 + 单独材质，混在 body 的普通混合里
   出不来"发光"的观感。而且特效帧通常比人物帧大，独立页面才好分配。
3. **可维护**：换一个施法特效只重打 `subaru_fx_cast` 的页，不碰人物主体。

## 2. 帧与页预算

| 骨架 | 页 | 帧尺寸 | 帧数 | 填充率 | 显存 |
|---|---|---|---|---|---|
| `subaru_body` | 4096² | 约 300×400（含 8px 边） | **112**（idle 40 / attack 24 / cast 20 / hurt 8 / die 20） | ~72% | 16.8 MB |
| `subaru_rig` | 2048² | 分件 13 块，最大 320×480 | 13 块 | ~50% | 4.2 MB |
| `subaru_fx_cast` | 2048² | 512² × 16 / 套 × 2 套 | 32 | ~85% | 4.2 MB |
| `subaru_fx_env` | 2048² | 512² × 16 / 套 × 2 套 | 32 | ~85% | 4.2 MB |
| 合计 | | | | | **29.4 MB**（+12.6 MB） |

对比现状：单页 229 帧、16.8 MB、pck 里 30.7 MB。新方案显存 +75%，但**帧数从 229 降到 112 的逐帧 +
骨架层补足**，观感反而更"活"（因为头发衣摆是连续运动的，不再是死的图）。

### 帧数怎么砍下来的

| 动画 | v1 帧数 | v2 帧数 | 省在哪 |
|---|---|---|---|
| idle | 61 | 40 | 呼吸交给骨架层（hips/chest 正弦），帧只做 2 个循环姿态 × 20 |
| attack | 19 | 24 | 加长：蓄力/挥出/收招三段，挥出补 8 帧（有拖影） |
| cast | 48 | 20 | 魔法特效移到 `fx_cast`，人物只留身体表演 |
| hurt | 26 | 8 | 只做受击反冲 + 回位，抖动交给骨架层 |
| die | 80 | 20 | 倒地用骨架层的髋部下沉 + body 层 20 帧 |

## 3. 逐帧部分：生成流水线

工具：`C:\Users\Elan\Desktop\dsh\4router-image\imggen.py`（`gpt-image-2`，已接 4router）。

### 3.1 阶段 A：定妆照（一次性，1 张）

```powershell
cd C:\Users\Elan\Desktop\dsh\4router-image
python imggen.py "Re:Zero 菜月昴，正面全身站姿，黑橙色运动服，白色短发，黑边外套，中性表情，纯透明背景，全身入画，脚底贴边，动画用立绘，干净线稿+赛璐璐上色" `
  --size 1024x1536 --quality high --background transparent --out "C:\Users\Elan\Desktop\塔2mod\_anim\ref\hero_base.png"
```

产出 3–4 张挑 1 张进 `_anim/ref/hero_base.png`。**这张是全套的唯一身份锚点**，后面每帧都拿它当 `--ref`。

### 3.2 阶段 B：关键姿势（每个动作 5–8 张）

```powershell
python imggen.py "同一角色：右手持短棒向前挥出，身体前倾，外套下摆甩起，面部用力，同一服装同一发型同一画风" `
  --ref "_anim\ref\hero_base.png" --input-fidelity high --size 1024x1536 --quality high --background transparent `
  --out "_anim\frames\attack\key_03.png"
```

要点：

| 项 | 做法 |
|---|---|
| 一致性 | **每一帧都带同一张 `--ref hero_base.png` + `--input-fidelity high`**，不要用上一帧当 ref（误差会累积） |
| 姿势控制 | 先用 3–4 张"草图 ref"（火柴人/灰模截图）做双 ref：`--ref hero_base --ref pose_sketch` |
| 尺寸 | 一律 `1024x1536`，后处理统一降到目标尺寸（避免每帧尺寸不同导致锚点漂移） |
| 背景 | 一律 `--background transparent`；生成不干净的帧用 `--mask` 局部重绘边缘 |
| 质量 | `--quality high`。每帧约 1.5k–2k token，112 帧 ≈ 20 万 token 量级 |

### 3.3 阶段 C：中间帧

两段关键帧之间用**双 ref**插：

```powershell
python imggen.py "介于这两张之间的过渡姿态，同一角色，同一镜头" `
  --ref "_anim\frames\attack\key_03.png" --ref "_anim\frames\attack\key_04.png" `
  --input-fidelity high --background transparent --size 1024x1536 --quality high `
  --out "_anim\frames\attack\key_03b.png"
```

一次只插 1 帧（不要一次要 3 帧，误差会放大）。插完做质检，不过就重插。

### 3.4 阶段 D：后处理（脚本，全自动）

每一步都是固定动作，写成 `_tools\anim\postprocess.py`：

1. **去背**：alpha 阈值 8，边缘 1px 羽化；半透明孔洞（发丝缝）用形态学补
2. **刚体配准**：每帧用「两眼中心 + 下巴」三点求相似变换（缩放/旋转/平移），
   把角色对齐到统一锚点（脚底中心 = 画布底部中心）
3. **统一调色**：取定妆照的平均色做 LAB 空间的白平衡校正，避免每帧亮度跳
4. **裁切 + 缩放**：按内容包围盒裁到 ≤300×400，缩放到目标尺寸（Lanczos）
5. **质检**：相邻帧 SSIM ≥ 0.80、锚点偏差 ≤ 2px，不过的帧进 `_anim/review/` 人工挑

### 3.5 阶段 E：打包成骨架

沿用现有 `_tools` 里的打包产物格式（`subaru.atlas` + `subaru.spine-json` + `_0.png`）：

- atlas 区域名 = `{anim}_{frame:04d}`（`idle_0000` …），`offsets:0,0,w,h`（和 ironclad 一致）
- 页面参数：`size:4096,4096 / format:RGBA8888 / filter:Linear,Linear / repeat:none`
- 导入设置：BPTC、mipmaps off、detect_3d=0
- spine-json 里 body 骨架保持 **1 骨 1 槽**，每帧一个 `attachment` 关键帧（和现在一样，稳）

## 4. 骨架部分：`subaru_rig`（二级运动）

复用 v1 文档里的骨骼层级，但**只保留真正需要的 13 根**（不做形变网格）：

```
root
├─ hips
│  ├─ torso → chest → neck → head
│  │  ├─ hair_back（2 段：hair_back_1 → hair_back_2）
│  │  ├─ hair_front
│  │  ├─ arm_l_u → arm_l_f
│  │  ├─ arm_r_u → arm_r_f
│  │  └─ coat_l / coat_r
│  └─ leg_l / leg_r（不做二级，body 帧已经画好了）
```

| 动画 | 时长 | 关键帧 | 说明 |
|---|---|---|---|
| `idle_breath` | 2.0 s | 5 | chest 缩放 1.00→1.02、head ±2°、hair_back 正弦 ±4°（相位滞后 0.15 s） |
| `hair_sway` | 1.6 s | 4 | 只用在后发/前发，和其它动画叠加 |
| `coat_flutter` | 1.2 s | 4 | 外套下摆 ±6°，相位差 0.1 s |
| `hit_react` | 0.5 s | 3 | 整体后仰 6°，头发/外套甩出 |

**叠加规则**：Spine 里不同动画只能选一个播，所以二级运动做成
「主动画里把 rig 的关键帧塞进同一时间轴」——即 `attack` 动画同时含手臂骨 + 头发衣摆的曲线。
工具侧：动画表写成 JSON（`_tools/anim/rig_anims.json`），由 `rig2spine.py` 合成进 spine-json。

## 5. 特效部分：`subaru_fx_cast` / `subaru_fx_env`

### 5.1 设计原则

| 原则 | 做法 |
|---|---|
| 加色混合 | 节点材质 `blend_mode = Add`；贴图底色纯黑（黑=透明，加色后只剩亮部） |
| 不画"整体特效" | 一个特效 = 2–3 个可独立运动的部件（核心 + 外环 + 碎屑），骨架各挂一根骨 |
| 帧数少而大 | 512² × 16 帧一段就够，靠缩放/旋转/透明度曲线撑"华丽" |
| 文字/法阵 | 法阵用 **1 张静态图 + 骨架旋转/缩放**，比逐帧省 15 帧 |

### 5.2 三套必做特效

| 特效 | 骨架 | 帧数 | 组合 |
|---|---|---|---|
| **魔法球**（施法） | fx_cast | 16（核心 8 + 光晕 8） | 手部 bone 绑定 + 缩放脉冲 + 加色 |
| **地面法阵**（范围/权能） | fx_env | 1 张 + 骨架 | 3 层同心环反向旋转 + 呼吸缩放 + 加色 |
| **死归时钟波纹**（专属） | fx_env | 12 | 波纹扩散 + 逆向播放表示时间倒流 + 全屏 shader 轻微色偏 |

### 5.3 生成命令示例

```powershell
# 魔法球核心（16 帧，纯黑底，加色用）
python imggen.py "青白色魔法能量球，中心高亮，边缘放射状光丝，纯黑背景，特效素材，无角色" `
  --size 512x512 --quality high --background opaque --out "_anim\fx\orb\orb_%02d.png"
```

> 生成是单张的，循环跑 16 次、每次改 prompt 里的「第 N 帧：能量球从收束到爆发」。
> 加色素材**不抠图**，直接黑底进图集（省一轮去背）。

### 6.2 场景与驱动

```gdscript
# subaru.tscn 结构（沿用现有 Visuals / SpellVfx，新增 Rig 与 EnvVfx）
Visuals        : SpineSprite  skeleton=subaru_body      animation=idle_loop
  Rig          : SpineSprite  skeleton=subaru_rig       （同画布，位置缩放默认）
  SpellVfx     : SpineSprite  skeleton=subaru_fx_cast   material: blend Add
  EnvVfx       : SpineSprite  skeleton=subaru_fx_env    material: blend Add（z 在 body 之后先画）
  ScreenFx     : Control + shader（全屏闪白/色偏）
```

```csharp
// 扩展现有驱动：主骨架是时间基准，其它层每帧抄 TrackTime
// （现有 SpellVfxDriver 只同步一层；新写 SpineLayerSync 支持 N 层 + 动画名映射）
foreach (var layer in _layers)          // rig / fx_cast / fx_env
{
    layer.TrackTime = _main.TrackTime;
    layer.Visible   = _animVisible[_main.CurrentAnim].Contains(layer.Name);
}
```

**时序对齐**：所有层动画名与 body 一致（`attack`/`cast`/`die`），长度 ≤ body 的时长；
因为 TrackTime 是抄的，长短不一致也不会错位 —— 短的自然播完停在末帧。

### 6.3 加色与 Z 序

| 层 | Z | 材质 |
|---|---|---|
| EnvVfx | 角色之后（先画） | Add，`no_depth_test` |
| Visuals(body) | 中 | 默认 |
| Rig | 角色之上 | 默认（分件要盖住 body 的对应部位） |
| SpellVfx | 最上 | Add |

## 9. 风险与兜底

| 风险 | 概率 | 兜底 |
|---|---|---|
| 逐帧 image 生成一致性差（脸/服装每帧变） | **高** | ① 每帧固定同一 ref + input_fidelity high；② 三锚点刚体配准 + LAB 调色；③ 实在不行，改「3D 灰模出姿势 → image2image 上色」的路子 |

## 10. 需要拍板的决策点

1. **要不要保留现有 229 帧版本作为 fallback**（旧骨架留着，出问题一键切回）
2. **人物帧分辨率**：300×400（清晰、占页）还是 256×340（省 40% 页面，游戏内放大略软）
3. **特效套数**：先做「魔法球 + 法阵」两套验证，还是直接上「+死归波纹 +剑光」四套
4. **美术风格**：沿用现在的赛璐璐厚涂，还是改成更亮的"番剧特效"风（影响全部 prompt 前缀）
