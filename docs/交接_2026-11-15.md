## 1. 构建与部署

```powershell
$env:TEMP="C:\Users\Elan\Desktop\塔2mod\_tools\tmp"; $env:TMP=$env:TEMP
$env:NUGET_PACKAGES="C:\Users\Elan\Desktop\塔2mod\_tools\nuget-packages"
$env:NUGET_HTTP_CACHE_PATH="C:\Users\Elan\Desktop\塔2mod\_tools\nuget-http"
Remove-Item dist\Subaru\Subaru.pck -ErrorAction SilentlyContinue
_tools\dotnet\dotnet.exe publish src\Subaru\Subaru.csproj -c Release --no-restore
python _tools\deploy_mod.py
```

要点：
- 游戏在跑时 `deploy_mod.py` 会 `PermissionError [WinError 32]`，先关游戏。
- 新图片会被构建流程自动 `reimport` 并打进 pck，不需要单独导入。
- `deploy_mod.py` 写入 `游戏目录\mods\Subaru`——也就是说**跑一次 deploy 就等于启用本地版**。
- 本地版与工坊版同时存在时，游戏只留一份并报 Warn：版本相同保本地、工坊版本更高则禁用本地。
- 切换脚本（ASCII，双击即可）：
  - `_tools\local_mod_on.bat`：`mods_disabled\Subaru` → `mods\Subaru`（维护时用）
  - `_tools\local_mod_off.bat`：`mods\Subaru` → `mods_disabled\Subaru`（让工坊版生效）

## 2. 死归系统（延续 11-14 的修复）

### 2.1 沙坑（无厌沙虫）的「吞人」是**我们自己**触发的

- 原版 `SandpitPower.AfterRemoved` 会跑一整套收尾：补间到沙虫嘴边 → finisher 音效 → `EatPlayerTrigger` → `Kill`。
- 回档时快照里没有沙坑、场上有一个，还原逻辑把它删掉 → 整套收尾跑了一遍。
- 修法：`SandpitGuard.Silent` 期间 `AfterRemoved` / `UpdateCreaturePositions` 前缀直接返回 `Task.CompletedTask`；
  沙坑自然归零时在 `AfterRemoved` **入口**拦截，只记账（`SchedulePendingDeath`），等下一个玩家回合再回档。

### 2.2 怪物私有状态

`_tools\IlDump --fields` 导出 `Models.Monsters.*` 全部实例字段，筛出 37 只带可变状态的怪，写进
`BattleSnapshot.MonsterScalarSpecs`（标量）与 `MonsterStateSpecs`（招式状态机 StateId）两张白名单表。

### 2.3 单卡临时状态

`CardExtraState` 记：附着（存**规范模型 + 层数**，回档 `ToMutable()` + `AfflictInternal` 重建）、临时关键词、强化等级、
`HasSingleTurnRetain / HasSingleTurnSly / ExhaustOnNextPlay / ExtraReplayThisTurn / IsDupe`、`TransformIntoAfterPlay`、`Enchantment`。

> 教训：不要存场上模型对象引用。`ClearAffliction` 会调 `ClearInternal()` 把对象清空，存引用等于存空壳。

### 2.4 状态锁链 / 腐蚀牌 / 眠特效 / 遗物

- 锁链的「本回合已绑几张」是数战斗历史里 `CardAfflictedEntry` 的条数，回档要把条目削回并写回 `boundCardPlayed`。
- 腐蚀牌出战斗用 **1 参** `RunState.AddCard`（2 参会 `set_Owner`）再入牌组，失败退消耗堆。
- 遗物伤害一律 `ValueProp.Move | ValueProp.Unpowered`（力量只加成 `IsPoweredAttack`）。
- 阳剑第 3 回合触发后 `RelicStatus.Disabled`，`AfterCombatEnd` 里必须 `NRelic.Reload()` 才能清 shader。

### 2.5 死亡闸门的新规则（11-15 下午）

**只有战斗进行中才允许死归**，其它地方死了就是真死。判据集中在 `DeathReturnSpike.RewindAllowedNow()`：
`CombatManager.IsInProgress && !IsOverOrEnding`，且 `RunManager` 未 `IsAbandoned / HasRunEnded / IsCleaningUp / IsGameOver`。

三处入口都过这一关：`CapLethalDamage`（致命伤害截断）、`PlayerDeathGatePatch`（直接 Kill）、`ForceRewindAsync`（手动按钮）。

- 修掉的 bug：**放弃本局会触发死归、连点三次卡死**。原版放弃的顺序是「先 `set_IsAbandoned`，再 `GuaranteeKillAllPlayers`」，
  那一下击杀被闸门当成战斗死亡接住了。以前只用愚者测放弃（没有傲慢因子）所以没暴露。
- 事件里死亡（审判「拒绝」、真理石板、深渊浴场「沉溺」等）现在也是真死，不回档。

### 2.6 Harmony 前缀 `return false` 的坑（0.1.2 修）

跳过返回 `Task` 的原方法时，**必须声明 `ref Task __result` 并赋 `Task.CompletedTask`**；
只写 `return false` 会让返回值保持 `null`，调用方 `await` 一下就 `NullReferenceException`。

踩过的两处：`CardAnimationPatch`（拦 `CreatureCmd.TriggerAnim("Attack")`）导致
**所有攻击牌打出后卡在屏幕上、伤害不结算**；`NoDiscardPatch`（拦 `CardCmd.Discard`）同类隐患。
表现极具误导性——崩在 `AttackCommand.Execute` 里，看起来像某张牌的问题。

### 2.7 0.1.3 平衡性调整与卡面优化

一揽（工坊更新说明的标题就是「平衡性调整和卡面优化」）：

| 卡 | 改动 |
|---|---|
| 英雄 | `15 × (1+瘴气数)` → **`14 + 8 × N`，升级 `18 + 10 × N`**，N 不设上限（详见下） |
| 黑蛇·疫病 | 新增全体 **3 层中毒**，升级 5 层（易伤/虚弱仍 3→4，自伤 5 不变） |
| E·M·T / E·M·M | 升级不再 `RemoveKeyword(Exhaust)`，只追加[保留] —— 之前升级版是 0 费可无限循环 |
| 宫廷小丑 | 每张技能牌伤害 3→**5**，升级 **8**（`UpgradeValueBy(3)`） |
| 嫉妒魔女·莎缇拉 | 升级不再给[固有]，改为**费用 3→2 + 每次死归伤害 15→17** |
| 嫉妒魔女·莎缇拉 | 卡面换图（源图 `_assets_work\src_satella_new.png`，656×497） |

「英雄」的细节：原写法是**乘倍**，瘴气一多就爆表（3 张 = 60，6 张 = 105），而瘴气本身不可弃牌、只会越攒越多，所以实测偏超模。
改为固定加算后实现上多一个 `IntVar("PerCurse", 8m)`（升级 `UpgradeValueBy(2m)`），卡面改成
`造成{Damage:diff()}点伤害…额外造成{PerCurse:diff()}点伤害`——两个数字要分别显示，就必须拆成两个变量。
仍然**不消耗瘴气**。

「莎缇拉」的细节：卡本身没有伤害数字，15 写死在 `DeathReturnSpike.ApplyRewindBlessing`。
现在基数存在 `SatellaPower.DamagePerRewind`（默认 15），打出时由卡牌写入（升级 17）；
该能力带【腐蚀】不随死归重建，所以这个字段能活过回档。卡面文案改成 `{Damage:diff()}`。

换单张卡面走 `docs\卡面脚本\recrop_card.py <源图> <card_id> [top|center]`（裁切规则与 `install_cards.py` 一致，顺带更新 `STATE.json`）。

### 2.8 腐蚀牌「死归复制」bug（0.1.4 修）

症状：同一局里凭空多出几张「强欲的契约」之类的[腐蚀]牌。

成因链：存档点在同一回合内不会刷新 → 那张腐蚀牌一直留在快照里 → 每次回档它的实例都已被销毁
（打出的牌会 `HasBeenRemovedFromState`），`RestorePile` 于是**重建一张新的** →
`CorrodedCards.Purge` 再把这张新实例退回牌组 → 牌组每死归一次多一张。

更隐蔽的一层：`Purge` 里本来有「已在牌组就跳过」的检查，但它用
`pcs.AllPiles` 找 `PileType.Deck` —— **`AllPiles` 只有手牌/抽牌/弃牌/消耗/出牌五堆，不含牌组堆**，
所以这个检查从来没生效过。要取牌组堆必须用 `CardPile.Get(PileType.Deck, player)`。

修法（两处）：
- `CorrodedCards.ReturnedToDeck` 记「本场已退回牌组」，`Purge` 遇到重复的替身直接跳过，牌组检查改成 `CardPile.Get`
- `BattleSnapshot.RestorePile` 重建前先看 `WasReturnedToDeck`，已退回的腐蚀牌不再造替身
  （只修 Purge 不够：替身会留在手里，玩家能再打一次）

旧存档里已经多出来的牌不会自动消失。曾经写过一个一次性清理补丁 `CorrodedDeckDeduper`
（开关文件 `subaru_dedupe.txt`，挂在 `PrideFactorSpike.BeforeCombatStart`），
但它在 0.1.4 里被**误随正式版一起发出去**了，0.1.5 已从构建中移除，
源码留档在 `_tools\legacy\CorrodedDeckDeduper.cs.txt`（不在 `src\` 下，不参与编译）。
要再启用就把它拷回 `src\Subaru\SubaruCode\Patches\` 并重新加回那行调用。

教训：临时调试补丁要放在 `src\` 之外，或者用 `#if` 之类的编译开关挡住，
否则「改代码 → 直接发布」的流程会把它一起带出去。

### 2.9 进休息处直接崩溃（0.1.8 修）

症状：走到休息处，画面卡住，整个游戏进程退出；`logs\godot.log` 里**没有任何托管异常**，
最后一行停在休息处场景实例化附近——极具误导性，看起来像休息处立绘坏了。

真正的证据在 Windows 事件查看器（`Get-WinEvent -LogName Application`，事件 ID 1026 的 .NET Runtime）：

```
NRunMusicController.UpdateTrack(RoomType) → GodotObject.Call(...) → 0xc0000005
  from RunManager.EnterRoomInternal ← RestSiteRoom.EnterInternal
```

反编译 `UpdateTrack(RoomType)` 才看清：切完歌之后，**只有当当前房间是休息处**时才多跑一句
`_proxy.Call(_updateCampfireAmbienceCallback, true)`（篝火环境音）。崩的就是这一句。

根因在我们自己的音乐接管：战斗开始时调了原版 `NRunMusicController.StopMusic()`。
它的 IL 除了停音乐，还会 `_proxy.Call(_stopAmbience)` 把环境音事件一起停掉，
并清空 `_currentTrack / _failedTrack`。等进了休息处，原版拿到的篝火事件已经是空壳 → 段错误。

修法：`SubaruMusic.StopVanillaMusicOnly()` —— 反射拿 `_proxy` 和静态 `_stopMusic`，
**只** `_proxy.Call(_stopMusic)`，环境音不碰；`_currentTrack/_failedTrack` 置空让原版出战斗后能重新播。
绝对不要再调 `StopMusic()`。

排查开关 `user://subaru_nomusic.txt` 就是这条假设的对照实验（存在即完全不接管音乐），
确认后已随 0.1.8 移除。

### 3.2 显示规则用的是原版机制

未满足前置的节点**连槽位都不显示**（不是灰显）。实现方式是原版接口：

- `SubaruCallEpoch.GetTimelineExpansion()` → 死亡回归 / 魔女时代的终结 / 暴食
- `SubaruRewindEpoch.GetTimelineExpansion()` → Love
- `SubaruWitchEndEpoch.GetTimelineExpansion()` → 帝国的剑狼 / 崩坏的开始

RitsuLib 判断「谁是根节点、谁挂在谁下面」（`ShouldShowUnobtainedModSlot` → `IsModTimelineRootSlot` → `TryHasExpansionChild`）
读的正是 `GetTimelineExpansion()`，所以不用自己过滤槽位列表。
（曾经用 Harmony 前缀拦 `NTimelineScreen.AddEpochSlots` 做过一版，已删除。）

### 3.3 三种解锁机制

1. **角色**（`Patches\SubaruUnlockPatch.cs`）：postfix 挂 `UnlockState.get_Characters`——
   `SUBARU_EPOCH_CALL` 已揭示就确保在列表里，没揭示就**移除**。所以角色真正由节点解锁，和原版一致。
   想调试时跳过解锁流程，把 `ForceUnlock` 置 true。
2. **功能**（`Rewind\RewindProgress.cs`）：跨局计数存 `user://subaru_rewind_total.txt`，三个死归入口各调一次 `Add()`；
   满 10 / 99 走 `SubaruEpochGranter.Grant<>()`（内部：`ProgressSaveManager.TryObtainEpochInternal` 反射，失败退化成写 `ProgressState._epochs`）。
   调阈值测节点：直接改这个 txt。
3. **卡牌**（`Character\SubaruCardPool.cs`）：`CardGates` 表把 14 张牌映射到节点 id（一张牌可挂多个节点，任一揭示即解锁）。

**发放时机**：`SUBARU_EPOCH_CALL` 挂在一局结束的两个出口（`RunManager.OnEnded` / `RunManager.Abandon`），
prefix 先抓住 RunState 再在 postfix 发放——这样解锁动画只在结算时播，不会一开局就弹。

### 3.4 立绘（三条路径全部接管）

`EpochModel` 三个路径属性都被 `Timeline\SubaruEpochPortraits.cs` 接管，只对 7 个自己的 id 生效：

| 属性 | 用途 | 给什么 |
|---|---|---|
| `RealPortraitPath` | 解锁弹窗 / 节点详情大图 | `<id>.png` |
| `PackedPortraitPath` | 时间线节点小图 | 已获得 `<id>.png`，未获得 `<id>_locked.png` |
| `PlaceholderPortraitPath` | 兜底 | `<id>_locked.png` |

- 未解锁图是**预先烘焙**的模糊+灰度图：`_tools\tmp\make_locked_portraits.py`，`R = 12` 改模糊半径。
- 尺寸统一 **1200×675**；路径 `res://Subaru/images/timeline/epoch_portraits/`。
- 槽位自己还会叠一层 `saturate=0 / value<1`，所以最终观感与原版未解锁节点一致。

### 3.5 文案

`src\Subaru\Subaru\localization\eng\epochs.json`（游戏里显示的就是这些中文，`eng` 只是目录名）：

- `STORY_SUBARU`（故事名）
- `<ID>.title` / `.description` / `.unlockInfo` / `.unlockText` / **`.unlock`**
  - `.unlock` 是**解锁角色页面顶部**那段大文字（`NUnlockCharacterScreen` 的 `%TopLabel`），缺了会显示成原始键名
  - `.unlockText` 是页面底部那行「解锁…」

- `characters.json` 的 `SUBARU-SUBARU.unlockText` 是选人界面**锁住时**的提示（`CharacterModel.GetUnlockText` 读 `characters.<id>.unlockText`），缺了会走 `LOCKED.title` 兜底并在日志报 missing key。

  - 技能牌 / 能力牌 → 不播
- 原版那条 `TriggerAnim(..., "Attack")` 被 `Patches\CardAnimationPatch.cs` 拦掉（否则魔法攻击会先挥一下再切施法），
  改由 `SubaruCard.PlayCardAnimation()` 直接调 `creature.GetCreatureNode().SetAnimationTrigger(...)`。
- 想给单张牌特事特办：override `IsMagicAttack`。

## 5. 存档（modded 分离与迁移）

- 游戏按「本次是否加载 mod」分两套存档根：`steam/<好友码>/profileN/` 与 `steam/<好友码>/modded/profileN/`。
- 原版只在 `modded/` 目录**完全不存在**时才整份复制一次；目录已存在就 `Modded saves exist. Skipping first-time save copy`，
  玩家会看到全新进度（装过别的 mod 的人几乎必然踩到）。
- 本 mod 补一刀：`Compatibility\VanillaSaveMigration.cs`，在 `MainFile.Initialize` 里跑——
  原版那份有 epoch、而 modded 那份不存在或 0 条 epoch 时，**单向**复制 `progress.save`；已有 modded 进度绝不覆盖。
  日志：`[Subaru] migrated vanilla progress -> modded (profile1, N epochs)`。
- 注意 `user://` = `%APPDATA%\SlayTheSpire2\`，账号目录在下一层（`steam/<好友码>`），没有 Steam 时只有一层——代码两层都探。

更新流程（详见 `release\workshop\Subaru\更新流程.txt`）：
改代码 → 重建 → 把 `dist\Subaru\{json,dll,pck}` 覆盖进 `content\` → 改 `changeNote` → 双击 `upload.bat`（`ModUploader.exe upload -w .`）。

**用户说「同步更新」= 这两件事**（2026-11-16 定）：

1. **同步卡牌表**：`python _tools\sync_cardtable.py` —— 从源码 + `localization\zhs\cards.json` 重算稀有度/费用/权能/关键词/描述/升级效果，只改数值格，样式和「来源/流派/备注」保持不变，旧表自动备份到 `docs\卡牌表.bak4.xlsx`，并打印每个被改的格。
2. **上传工坊**：覆盖 `content\` → 换 `changeNote`（**只写英文**）→ `_tools\tmp\make_release_pkg.py` 出 zip → `ModUploader.exe upload -w .` → 把同一份内容的**中文版发在对话里**给用户，中文由用户手动上传。
   上传成功的判据：日志出现 `Successfully uploaded`，再用 Steam Web API（`ISteamRemoteStorage/GetPublishedFileDetails`）核对 `time_updated` 和 `file_size`。

坑：
- **`changeNote` 两条**：① 只写这一次的改动，别把上一次的条目再抄一遍（工坊本身按版本留历史，
  混进来玩家会以为那些东西又改了一次）；② 只写「改了什么 / 修好了什么」，**不写原因、不写实现方案**
  （修 bug 就一行「修复：<玩家能感知到的现象>」，内部成因写在本文档里）。每次整条替换，不追加。
  0.1.4 两条都犯了，用户当场指出。
- **`changeNote` 上传时只放英文**（2026-11-16 用户定）：中文版同一份内容写在对话里发给用户，由用户手动上传中文版；
  英文术语跟 `localization\eng\*` 一致。页面简介仍写在 `release\workshop\Subaru\发布文案.md`（双语，开头带一行「翻译由 AI 生成，可能不准确」），
  上传器不发简介，全靠手动粘贴。
- **中文文案里的卡名 / 能力名必须照抄 `localization\zhs\*`，不许从类名或英文名反推**（2026-11-16 用户定）：
  写 changeNote 时把「愤怒司教·洗魂」写成了「天狼星：魂洗」——角色称号当成了牌名，字还写反；
  同一句的「乌尔·纱幕」漏了中间的点。用户当场指出，线上文案由用户手动改的，本地已同步订正版。
  做法：动笔前先去 `zhs\cards.json` / `zhs\powers.json` / `zhs\relics.json` 的 `.title` 里查一遍，照抄。
  这条不限于工坊文案，所有中文产出（文档、说明、交接）都同样适用。
- `-w` 是工作区**目录名**，在目录内要用 `.`；写成 `-w Subaru` 会报 `No directory at Subaru!`
- `upload.bat` 里不能写中文（cmd 按 GBK 读 UTF-8 会解析失败、窗口一闪就关）
- 缺 `steam_api64.dll` → `DllNotFoundException ... SteamAPI_Init`
- `workshop.json` 里 `title / description / visibility / minBranch / maxBranch` 已删空，
  交给工坊页面手动维护；保留这些字段会在每次更新时覆盖网页上的改动
- tags 上传后不能改；当前 `Characters / Cards / Relics / schinese`
- 工坊物品默认语言固定英语（上传器不发语言字段），中文文本放在英语槽里，中文玩家照样看到

反编译常用：
```powershell
_tools\dotnet\dotnet.exe _tools\IlDump\bin\Debug\net9.0\IlDump.dll `
  "D:\SteamLibrary\steamapps\common\Slay the Spire 2\data_sts2_windows_x86_64\sts2.dll" `
  "SandpitPower"
```
输出写到 `_tools\IlDump\bin\Debug\net9.0\il_out.txt`（`--calls` / `--fields` 分别写 `callers_out.txt` / `fields_out.txt`）。

日志：`%APPDATA%\SlayTheSpire2\logs\godot.log`，游戏运行中会被占用，用
`[System.IO.File]::Open($log,'Open','Read','ReadWrite')` + UTF8 StreamReader 读，直接 `Get-Content` 会因 GBK 控制台变乱码。

存档路径：`%APPDATA%\SlayTheSpire2\steam\<好友码>\` 下 `profileN/`（原版）与 `modded/profileN/`（modded）；
备份都在 `_tools\save_backup\`。
