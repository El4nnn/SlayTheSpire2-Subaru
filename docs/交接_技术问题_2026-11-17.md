# 交接 · 技术问题 2026-11-17：死归（回档）与原版内容的兼容性

> 📌 **active** ｜ 最后核对：2026-11-23 ｜ 根因：快照覆盖面 / 遗物 / 柯尔

> 一次系统性排查的记录。**以后遇到「死归之后某个东西不对」，先看这篇**，再动手。
> 配套：`docs\原版遗物_死归风险筛查.xlsx`（312 件原版遗物分级）、`docs\构建与部署.md` §1.5（测试补丁纪律）。

## 0. 一句话结论

死归不是「把状态存下来再写回去」这么简单。`BattleSnapshot` 只覆盖**生物 / 牌堆 / 能量 / 星 / 能力 Amount / 部分卡牌状态**；
原版有四大类效果不在覆盖范围内，它们的共同表现是「死归后某个一次性效果消失、计数错位、或者白送资源」。
本次定位并修掉这四类，判据全部来自 IL 实证。

## 1. 四类问题（症状 → 根因 → 修法 → 日志）

### 1.1 战斗开始的一次性效果被吞 —— 面包（BREAD）

**症状**：面包只在整场战斗第一回合扣 2 能量；死归之后不再扣，等于每死一次白拿 2 能量。

**根因（IL 实证）**

`CombatManager.StartTurn` 的顺序：

```
BeforeSideTurnStart → AfterBlockCleared → SetupPlayerTurn → AfterSideTurnStart
```

我们的初始快照抓在 `AfterPlayerTurnStartLate`（`SetupPlayerTurn` **内部**），也就是 `AfterSideTurnStart` **之前**。
而 `Bread.AfterSideTurnStart` 靠 `PlayerCombatState.TurnNumber == 1` 判断（遗物自身没有任何状态），
`Bread.ModifyMaxEnergy` 同理。所以快照里的能量是「还没扣过的满值」，还原后这个钩子又不会重跑 → 扣费永久消失。

**修法**：`Spike.ReplayAfterSideTurnStartAsync`

- 条件：用的是**初始快照**（不是手动存档点）且复原后 `TurnNumber == 1`
- 动作：`await Hook.AfterSideTurnStart(state, CombatSide.Player, participants)`
- 依据：快照语义本来就是「这个钩子执行前的瞬间」，补跑一次正好补上原时间线的那一次

**必须注意的顺序**

1. 必须在 `RelicStateSnapshot.Restore` **之后**补跑 —— 否则开心小花这类在该钩子里 `_turnsSeen++` 的遗物会少算一次
2. 手动存档点**不补**（它本来就拍在钩子之后，效果已包含）
3. 补跑期间 `CurrentSide` 是 Player（两条还原路径都是等回合机走到玩家回合才还原），不需要额外切 side

**日志**：`[Subaru] after-side-turn-start replayed (turn 1 restore), energy=1`

### 1.2 牌被重建时丢「本场费用覆盖」 —— 宝石面具（JEWELED_MASK）

**症状**：面具给的那张「本场免费」能力牌，死归之后变回满费。

**根因**

- 能力牌（`CardType.Power`）打出后实例被销毁（`HasBeenRemovedFromState = true`）
- 回档时 `RestorePile` 走 `Rebuild()`，按原型 `state.CreateCard(canonical, player)` 新建，**只复制升级状态**
- 而「本场免费」不在原型上：`SetToFreeThisCombat()` → `EnergyCost.SetThisCombat(0, false)` → 往 `_localModifiers` 里加一个 `LocalCostModifier(Expiration = EndOfCombat)`

**修法**

| 位置 | 内容 |
|---|---|
| `CardExtraState` | 新增 `CombatEnergyCost` / `CombatStarCost` |
| `CaptureCardStates` | 记 `card.EnergyCost?.GetResolved()` 和 `card.GetStarCostThisCombat()` |
| `Rebuild` | 重建后调 `ApplyCombatCostOverride(card, st)` |
| `ApplyCombatCostOverride` | `EnergyCost.SetThisCombat(cost, reduceOnly: true)` + `SetStarCostThisCombat(stars)` |
| `PlayedPowerCards` | 打出那一刻把费用记进 `Entry`，复制回手牌时同样写回 |

**细节**

- `CardEnergyCost.GetResolved()` 的 IL：X 费牌返回 `CapturedXValue`，其余返回 `Max(0, GetWithModifiers())` —— 确实包含本地修正
- `SetThisCombat(cost, reduceOnly)` 自带保护：`cost == 0 && Canonical < 0` 直接 return，**X 费牌不会被误设成 0 费**
- `reduceOnly = true`：只还原「变便宜」，不把临时涨价固化下来
- 全项目的 `state.CreateCard(` 只有两个属于回档路径（`Rebuild`、`PlayedPowerCards`），两处都补了

**日志**：`[Subaru] restored combat cost: CARD.X -> 0`

### 1.3 遗物实例字段不随快照回滚 —— 投斧 / 蜥蜴尾巴 / 律动残余 / 苦无 …

**症状**：一场一次的效果被吞（投斧首牌双打、蜥蜴尾巴保命、臂甲首次格挡翻倍、永冻冰晶首次能力牌格挡…），
或者回合内计数错位（苦无/手里剑/折镰的「每 3 张攻击」、钢笔尖的「第 10 张攻击」）。

**根因**：遗物是跨战斗的长命对象，`BattleSnapshot` 完全不碰它们。
原版大量遗物把「本场有没有用过 / 本回合打了几张」记在实例字段里。

**修法**：`Rewind/RelicStateSnapshot.cs`

- 抓快照：把每件遗物的**简单字段**（bool / 整数 / 浮点 / decimal / string / 枚举 / 它们的 `Nullable`）读一份
- 回档：原样写回；引用型字段（卡牌、能力、Task、List）一律跳过
- 实现要点：
  - 取字段要「沿继承链逐层 `DeclaredOnly`」，`GetFields()` 拿不到基类私有字段
  - 值比较用 boxed `object.Equals`，只写真正变化的字段（日志里的 field 数就是改动数）
  - `player.Relics.Contains(relic)` 兜底：遗物被换掉/卖掉就不写
- 与我们自己的遗物不冲突：梦剑 / 谈心镜 / 阳剑本来就实现 `IRewindCounterRelic`，通用快照只是重复写同值

**日志**：`[Subaru] relic state captured: N relic(s), M field(s)` / `[Subaru] relic state restored: K field(s)`

### 1.4 战斗历史不回滚 —— 历史课（HISTORY_COURSE）/ 情感芯片

**症状**：历史课在死归后可能重放「被打回那段时间线」里的攻击牌；依赖「本回合/上回合有没有…」的遗物读到假数据。

**根因**：`CombatHistory` 的条目只有状态锁链那部分被回滚（`RestoreChainsState`），其余条目不回滚。
历史课的判定是 `Enumerable.LastOrDefault<CardPlayFinishedEntry>`。

**修法**：`BattleSnapshot.HistoryCount` + `RestoreHistory()`

- 抓快照：记 `CombatHistory._entries.Count`（反射，公开的 `Entries` 只是只读 `IEnumerable`）
- 回档最后一步：`while (entries.Count > HistoryCount) entries.RemoveAt(entries.Count - 1)`
- 必须在所有「补账」动作（补能力/补诅咒/补遗物状态）**之后**调用，连还原过程产生的条目一起抹掉
- `HistoryCaptured` 标志位：抓失败就不截，否则会把整条历史清空

**日志**：`[Subaru] history truncated: X -> Y entries` / `[Subaru] history unchanged: …`

## 2. 同日修掉的同类问题：柯尔·雷欧尼斯

- 原实现把「武装（结束减伤窗口）」挂在**玩家回合结束**，而 `EndPlayerTurnPhaseTwoInternal` 触发
  `AfterSideTurnStart(Player)` 是在 `SwitchFromPlayerToEnemySide` **之前** —— 等于敌人还没出手，减伤就没了
- IL 判据：`CombatManager/<AfterAllPlayersReadyToBeginEnemyTurn>d__148::MoveNext` 里
  `@0126 call EndPlayerTurnPhaseTwoInternal` → `@018A call SwitchFromPlayerToEnemySide`
- 已改成**敌人回合结束**武装、下一个玩家回合结束还债

**教训（通用）**：任何「本回合内有效」的效果，要知道「本回合」在引擎里到底覆盖到哪一段钩子。

### 2.1 顺带修掉：同一回合打两张会把状态位「加」坏

`CorLeonisPower` 把「欠多少伤害 / 是否升级 / 是否已武装」编码进 `Amount`（死归只恢复 Amount，必须这么做）：

```
Amount = 1 + (pending << 2) + (upgraded ? 2 : 0) + (armed ? 1 : 0)
初始值：未升级 1，升级 3
```

而 `PowerCmd.Apply` 对**已存在的同类实例**是**相加**而不是替换（IL 实证，
`PowerCmd/<ModifyAmount>d__6::MoveNext`：`newAmount = power.Amount + (int)offset; power.SetAmount(newAmount)`）。
所以旧版第二张牌的 `InitialAmount` 会直接加到编码位上：

| 两张牌 | Amount | 解出来的状态 | 表现 |
|---|---|---|---|
| 未升级 + 未升级 | 1+1 = 2 | pending 0 / 升级 false / **armed true** | 立刻被判成「已武装」→ 本回合不减伤、下回合结算 0 后移除（两张都白打） |
| 未升级 + 升级 | 1+3 = 4 | pending 0 / 升级 true / armed true | 同上，还白记一个升级位 |
| 升级 + 升级 | 3+3 = 6 | pending 1 / 升级 false / armed true | 债务读成 1、升级位丢失 |

**修法**：卡牌先查场上有没有现成实例；有就调 `CorLeonisPower.Reapply(upgraded)`，
`Encode(Pending, UpgradedFlag || upgraded, armed: false)` —— 债保留、窗口重开、升级位取或。
**不要再对同一个能力调 `Apply`**：任何把 `Amount` 当数据位用的能力都踩这个坑。

## 5. 仍未覆盖 / 已知边界

1. **引用型字段不还原**：音乐盒 `_cardBeingPlayed`、不安油灯 `_doubledPowers`、佩尔士兵 `_affectedCardPlay`、钢笔尖 `_attackToDouble`。
   硬塞旧引用会指向已被快照删除的对象（半死对象），宁可不动；实际影响都很小。
2. **存活牌上被打回时间线加过的「本场」减费不会撤回**：引擎只清「本回合」型的（`EndOfTurnCleanup`），
   `reduceOnly` 的语义也不允许把费用「抬回去」。原版只有书签沾边，且它是本回合型。
3. **弃物字段快照只记第一个玩家**（和 `RelicCounterSnapshot` 一致），多人场景未覆盖。
4. **`_isActivating` 这类纯演出标记也会被写回**：无害，最多某个高亮动画提前收掉。

## 6. 临时补丁的分发纪律（2026-11-17 踩坑）

- **遗物类测试补丁：跟初始遗物一起发** —— 挂 `Player.PopulateStartingRelics` 后置，
  `player.AddRelicInternal(relic, -1, silent: false)`
- **不要**在战斗开始时发：`AddRelicInternal(..., silent: true)` 只把遗物塞进 `_relics`，
  **不触发 `RelicObtained` 事件**，遗物栏不刷新。
  实测：日志里 `granted relics` 全打出来、`relic state captured: 10 relic(s)` 也对，但玩家界面上一个都看不到
- 牌 / 怪物同理：走游戏自己的入口（初始牌组、遭遇表），别在战斗中途硬塞
- 详见 `docs\构建与部署.md` §1.5
