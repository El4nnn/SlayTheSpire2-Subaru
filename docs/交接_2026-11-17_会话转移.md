## 5. 双版本（release / beta）实验：已搁置

产物、脚本、日志、结论全部归档在 **`_tools\frozen\dual_variant_20261117\`**，README 里写了：

- β（0.113.1）：双版本包**实测通过**
- 默认分支（0.111.1）：**起不来**，崩在 `BaseLib.Patches.PostModInitPatch.LatePostInit`
  → `TypeLoadException: MegaCrit.Sts2.Core.Entities.Multiplayer.LobbyPlayer`
  同一次会话里**奶蛙也一起挂**，判断是工坊这版 BaseLib/RitsuLib 对 0.111 本来就不成立，与我们的包无关

三条能直接复用的关键结论：

1. 引导器的**程序集名不能和真 dll 重名**（`Subaru.Variants` vs `Subaru`），否则同 ALC 撞身份
2. 变体 dll **必须加载进 BaseLib 所在的 `AssemblyLoadContext`**（`AssemblyLoadContext.GetLoadContext(baseLibAsm)`），
   加载到 Default 会出两份 BaseLib，所有 override 报 `does not have an implementation`
3. 版本读游戏根目录 `release_info.json` 的 `version`；`res://` 在 mod 初始化阶段还不可用

什么时候捡起来：BaseLib 明确支持 0.111 时 / 默认分支升到与 0.113 同代 API 时 / 官方 1.0 出来时。
