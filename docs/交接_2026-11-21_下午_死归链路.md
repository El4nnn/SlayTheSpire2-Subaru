## 1. 立即死归 = 自伤 + 延迟交回合 + 跳过敌方

### 1.1 现在的链路

```
按下按钮
 → 自伤：CreatureCmd.Damage(self, MaxHp, Unblockable)，包在 MiasmaBleed 作用域里
 → CapLethalDamage 压成 hp-1（1 血时压成 0 伤害）、记死亡、紫闪、早期倒下演出
 → 兜底：若没被打死（减伤/伤害上限）→ SchedulePendingDeath 手动记一次
 → 排队 1.0 秒（给玩家看倒下）
 → 等手牌空闲 → SkipEnemyTurn = true → SetReadyToEndTurn(player, canBackOut:false, null)
 → 敌方回合：每个 Creature.TakeTurn 被跳过；EndEnemyTurn 照常执行（不会软锁）
 → 下个玩家回合 OnPlayerTurnStart → 还原
```

### 1.2 为什么这样改

- **注能（Imbued）**：它的触发条件是"第 1 回合的 auto-pre-play 阶段"。原来自伤式还原发生在**回合中途**，那个阶段已经跑过 → 注能永久不出手。
  现在还原发生在 `AfterPlayerTurnStartLate`（`SetupPlayerTurn` 内部），而 `RunAutoPrePlayPhase` 在它之后 → 阶段会正常跑。
- **跳过敌方**：`CombatManager.ExecuteEnemyTurn` 的方法体末尾负责 `EndEnemyTurn`，整个跳过会软锁；所以切在 `Creature.TakeTurn`（见 `Patches/SkipEnemyTurnPatch.cs`）。

### 1.3 改动点

| 文件 | 内容 |
|---|---|
| `Rewind/Spike.cs` `ForceRewindAsync` | 自伤 + 兜底 + 排队；不再当场 `RestoreToSavepointAsync` |
| `Rewind/Spike.cs` `CapLethalDamage` | 第一次记死亡后调 `ScheduleForceEndTurn(player)` —— **所有玩家回合内的自然死亡**都会延迟 1 秒交回合 |
| `Rewind/Spike.cs` 新增 | `SelfDamageForRewindAsync` / `ScheduleForceEndTurn` / `ForceEndTurnAsync` / `IsHandBusy`、字段 `SkipEnemyTurn`、`_manualInFlight`、`_forceEndTurnPending` |
| `Rewind/Spike.cs` `OnPlayerTurnStart` / `ResetForCombat` | 清 `SkipEnemyTurn`、解 `_rewinding` |
| `Patches/SkipEnemyTurnPatch.cs` **新文件** | `Creature.TakeTurn` 前缀，标记在时直接返回 `Task.CompletedTask` |

### 1.4 三个踩过的坑（都很容易复发）

1. **`_rewinding` 不能当"防连点"用**：`CapLethalDamage` 第一行 `if (_busy || _rewinding || !IsPlayer) return amount;`，
   在自伤前把 `_rewinding` 置 true → 截断放行 → 1 血角色被自己打死。改用 `_manualInFlight` 防连点。
2. **等待还原的窗口里伤害仍必须截断**：守卫改成
   `if (_busy || (_rewinding && !_pending) || !IsPlayer)`。
   否则 `_pending` 已记、`_rewinding` 为 true 的那 1 秒里，回合末瘴气/毒会真把 1 血角色打死。
3. **1 血时 `hp-1 = 0`**：截断返回 0 = 这一下不掉血，人不会死；这是正确行为，不要"修正"成至少 1 点伤害。

## 2. 能力药水 / 选择界面：两个"白赚一张"的口子

### 2.1 药水给的能力牌被死归补回手牌

- 现象：力量/能力药水选的牌，死归后还在手里（药水也回来了 → 净赚）。
- 根因：`PlayedPowerCards` 按**原型**记账，"打出过的能力牌，死归后补回手牌"。
  药水给的是**本场生成**的牌，但记账分不出来；`RestorePiles` 把它当临时牌删掉后，
  `RestoreAsync` 又按原型造一张塞回手牌（日志：`removed temp card` 紧跟 `restored power card to hand`）。
- 修法：`BattleSnapshot.ContainsCard(card)` + `DeathReturnSpike.SavepointContainsCard`，
  `Record` 时存 `InSnapshot`，还原时跳过 `false` 的条目。

### 2.2 选牌不选、点死归、再选 → 白赚一张

- 现象：药水开选牌 → 不选，按死归 → 死归后再选，牌加到**还原后**的手牌。
- 根因：选牌是 `ICardSelectionScreen.CardsSelected()` 的 await，引擎**没有 Cancel 接口**；
  死归只是换了状态，选完 potion 照样 `AddGeneratedCardToCombat`。
- 修法（D 方案）：`RewindButtonFollow.IsCardSelectionOpen()` 扫场景树里可见的 `ICardSelectionScreen`，
  选牌期间按钮变灰 + `ForceRewindAsync` 里二次拦截。
- 原版语义参考：`CardSelectCmd` 每个选牌入口都会 `UndoEndTurnIfNecessary`（结束回合让位给选择）。

## 4. 懒惰（Sloth）层数不回档

- 现象：恐惧模式、关底 boss 是知识恶魔时，普通战斗里死归后「懒惰」层数不回去。
- 根因：`SlothPower` 把计数放在**私有实例字段** `_cardsPlayedThisTurn` 上
  （`BeforeCardPlayed` +1、`BeforeSideTurnStart` 清零、`get_DisplayAmount` 直接显示它）。
  我们的 `PowerState` 只存 `Amount / AmountOnTurnStart / DynamicVars`，**不覆盖私有字段**。
- 修法：`PowerState.Fields`（`Dictionary<string,int>`）+ 白名单 `PowerCounterFields`，
  反射读/写 `SlothPower._cardsPlayedThisTurn`，在能力还原的两条分支（复用 / 重建）里各盖一次。
- 注意：`EncorePower` / `ChainsOfBindingPower` 的计数在内部 `Data` 对象里（`GetInternalData<Data>()`），
  直字段拿不到，**暂未纳入**；它们哪天出问题要另写读法。
- 验收日志：`[Subaru] power field restored: SlothPower._cardsPlayedThisTurn 2 -> 0`

## 6. 本轮新增的可复用结论

1. 判断"这张牌是不是本场生成的"：拿**实例引用**去问快照（`BattleSnapshot.ContainsCard`）。快照存的是对象引用，牌被打出也不会失效。
2. 想跳过敌方回合：切 `Creature.TakeTurn`，**不要**切 `CombatManager.ExecuteEnemyTurn`（后者负责 `EndEnemyTurn`）。
3. 想要"死亡手感"但又要走自然死亡路径：对自己来一次 `Unblockable` 伤害，别直接改 HP —— 引擎的判定、演出、记账全在伤害链里。
4. 能力把计数藏在私有字段里时，快照只还原 `Amount` 是不够的：要走白名单反射（`PowerState.Fields`）。
