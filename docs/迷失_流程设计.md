## 一、两层存档模型

| 层级 | 存档点 | 实现 | 状态 |
|---|---|---|---|
| **默认** | 战斗第 1 回合 | 进战斗时 `SaveRun` → 死亡后回主菜单 →「继续」 | ✅ 已实测可用 |
| **迷失** | 打出该牌的回合 | 打出时主动 `SaveRun` 覆盖存档 | ⏳ 待验证 |

---

## 二、完整流程

```
进入战斗
   └─ BeforeCombatStart
        └─ SaveRun(room)           ← 存档点 = 第 1 回合
             │
第 N 回合
   └─ 打出「迷失」
        └─ SaveRun(room)           ← 存档点 = 第 N 回合（覆盖）
             │
任意回合死亡
   └─ 致命伤害锁到 1 血
        └─ 下个玩家回合开始
             └─ ReturnToMainMenu()
                  └─ MainMenu.OnContinueButtonPressedAsync()
                       └─ 读档 → 回到存档点
```

## 三、关键代码

**存档（进战斗）**

```csharp
public override async Task BeforeCombatStart()
{
    var room = RunManager.Instance?.State?.CurrentRoom;
    if (room != null)
        await SaveManager.Instance.SaveRun(room, true);
}
```

**存档（迷失）**

```csharp
var room = CombatState?.RunState?.CurrentRoom;
await SaveManager.Instance.SaveRun(room, true);
```

**读档（死归）**

```csharp
await NGame.Instance.ReturnToMainMenu();
await Task.Delay(800);
await NGame.Instance.MainMenu.OnContinueButtonPressedAsync();
```

## 四、可行性判断（已预判的三处风险）

| # | 风险 | 说明 | 兜底 |
|---|---|---|---|
| 1 | **存档粒度为房间级** | `SaveRun` 可能只存「进入房间时」的状态，迷失写的档读回来仍是第 1 回合 | 改用内存快照（已实现，`BattleSnapshot`），代价是牌堆不恢复 |
| 2 | **退出时覆盖存档** | `ReturnToMainMenu` 可能自己再存一次，把迷失的档冲掉 | 读档前先备份存档文件，读档后还原 |
| 3 | **读档失败后死锁** | 已加 `OnFailed` 回调复位锁血状态 | ✅ 已修 |

## 五、验证步骤（一次就能判定走哪条路）

1. 进战斗，打到第 3 回合
2. 打出「迷失」
3. 日志应出现：`[Subaru] savepoint moved at turn 3`
4. 继续打，故意死
5. 读档完成后看当前回合数：
   - **是第 3 回合** → 方案 A 成立，迷失直接可用
   - **是第 1 回合** → 方案 A 不成立，切方案 B（内存快照）

---

## 六、方案 B（备用）：内存快照式迷失

如果原生存档只有房间粒度，则「迷失」改为：

1. 打出时：`BattleSnapshot.Capture(state)` 存一份内存快照，标记 `manual = true`
2. 死亡时：不走读档，直接 `RestoreFull()` 恢复：
   - 血量、格挡、能力层数、敌人血量/意图、回合数
   - 牌堆**不恢复**（避免之前的悬空牌问题）
3. 恢复失败 → 回退到原生读档

代价：打出的牌不会回来；但不会黑屏、速度更快。
