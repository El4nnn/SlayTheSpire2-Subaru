## 坑 1：NuGet 写不进 AppData（2026-11-13）

症状：

```
Access to the path 'C:\Users\Elan\.nuget\packages\alchyr.sts2.baselib\3.4.8\xxx' is denied
Access to the path 'C:\Users\Elan\AppData\Local\NuGet\v3-cache\...\list_xxx.dat-new' is denied
```

- ACL 看着正常（Elan 有 FullControl），手工 `New-Item` 也能建目录，但 **dotnet 进程写不进去**
- 结果是 `restore` 失败 → `csproj` 里 `Version="*"` 的 BaseLib 卡在旧版 3.4.7

解决：把包缓存和 http 缓存临时指到工作区（两行环境变量，见上面的流程）。做完之后：

- `_tools\nuget-packages\alchyr.sts2.baselib\3.4.8\lib\net9.0\BaseLib.dll` = **1,137,664 B**，
  和 workshop 线上那份 `3737335127\BaseLib\BaseLib.dll` 字节数一致，说明编译期/运行期同一版本
- `--no-restore` 的构建会沿用 `project.assets.json` 里锁定的版本（现在是 3.4.8）

## 坑 2：Godot 是 GUI 子系统

必须用 `Start-Process -Wait`，直接 `& $exe` 会立刻返回（导入没跑完就以为完成了）。

## 坑 3：新页/新贴图的导入预设

新建的 `.png` 会被 Godot 用默认设置（无损 + 非 VRAM），显存翻 4 倍。必须手动补：

```
compress/mode=2
compress/high_quality=true
mipmaps/generate=false
detect_3d/compress_to=0
```

## 打临时补丁（本地热修，不传工坊）

**用途**：改完代码先在本地验证，不上工坊、不 bump 版本。全部步骤走完约 3 分钟（不含游戏启动）。

### 0. 先确认游戏版本

```powershell
Get-Content 'D:\SteamLibrary\steamapps\common\Slay the Spire 2\release_info.json' -Raw
```

看 `version` 字段：`v0.113.1` = 测试分支（β），`v0.111.x` = 默认分支。
**版本换了要重新对参数**：`min_game_version`、RitsuLib 的 `compatTarget`、`_tools\refs\sts2-<target>\` 都可能要跟着换。
分支不对就别急着构建，先切回来。

顺手再看一眼 `mods\Subaru\Subaru.json` 的 `version`，确认装的是什么包（现在本地是 0.3.3，工坊线上是 0.3.2，两者本来就不同步）。

分支不对时，mod 的表现**不是报错，而是完全不生效**：进游戏看不到角色、日志里一条 `[Subaru]` 都没有。
很容易误判成「补丁没打上」或「补丁写错了」—— 2026-11-17 上午就卡在这个状态（游戏 0.111.1，包是 0.113 的），
切回 0.113.1 后一切正常。

### 1. 改代码

只改要验证的那一处。**一次只验一件事**：同时改三处，出问题不知道是哪一处引起的。

### 1.5 测试补丁的分发纪律（2026-11-17 定）

**遗物类测试补丁：跟初始遗物一起发。**

- 挂 `Player.PopulateStartingRelics` 的**后置**，用 `player.AddRelicInternal(relic, -1, silent: false)` 追加
- **不要**在战斗开始时发（`PrideFactorSpike.BeforeCombatStart` 那条路已验证不可行）：
  `AddRelicInternal(..., silent: true)` 只把遗物塞进 `_relics` 列表、**不触发 `RelicObtained` 事件**，
  遗物栏不刷新 —— 日志里 `granted relics` 全打出来了、`relic state captured: 10 relic(s)` 也对，
  但玩家界面上一个都看不到
- 同类经验：牌 / 怪物也用游戏自己的入口（初始牌组、遭遇表），别在战斗中途硬塞；
  硬塞要额外处理 UI 事件和 `HasBeenRemovedFromState`
- 原理与踩坑细节见 `docs\交接_技术问题_2026-11-17.md`

### 2. 构建

```powershell
cd C:\Users\Elan\Desktop\塔2mod
$env:TEMP = "C:\Users\Elan\Desktop\塔2mod\_tools\tmp"
$env:TMP = $env:TEMP
$env:NUGET_PACKAGES = "C:\Users\Elan\Desktop\塔2mod\_tools\nuget-packages"
$env:NUGET_HTTP_CACHE_PATH = "C:\Users\Elan\Desktop\塔2mod\_tools\nuget-http"

Remove-Item dist\Subaru\Subaru.pck -Force -ErrorAction SilentlyContinue   # 不删会跳过导出
_tools\dotnet\dotnet.exe publish src\Subaru\Subaru.csproj -c Release --no-restore
```

判成功：`dist\Subaru\Subaru.dll` 与 `dist\Subaru\Subaru.pck` 的**时间戳都是刚才**。
`MSB3073 exit -1` / `error saving editor settings` 是噪音，不影响。

> **只改 C# 时**可以用更快的 `build`（不出 pck，`dist\Subaru\Subaru.pck` 时间戳不变属正常）：
> `_tools\dotnet\dotnet.exe build src\Subaru\Subaru.csproj -c Release --no-restore`
> `build` 同样会经 `CopyToModsFolderOnBuild` 把 dll / json / pdb 拷进 `dist\Subaru\`，
> 所以下面的部署照旧用 `dist`，不用去 `src\Subaru\.godot\mono\temp\bin\` 里翻产物。
>
> ⚠️ **只要动了 `src\Subaru\Subaru\localization\` 下任何一个 JSON，就必须 publish，不能只 build。**
> 三语 `cards.json` 等是打进 **pck** 的，dll 里一个字都没有。2026-11-17 实测：改完文案只 build，
> 游戏里卡面还是旧字，最后靠 `pck` 字节比对（新文案 in pck = False → publish 后 True）才确认。

### 3. 先验产物，再部署

**别跳过这一步。** 部署一个没编进去的 dll 是最常见的时间浪费。

```powershell
# a) dll 里有没有你新加的类型/方法（用 IL 直接查，不靠猜）
_tools\dotnet\dotnet.exe _tools\IlDump\bin\Debug\net9.0\IlDump.dll `
  dist\Subaru\Subaru.dll "SlowPowerStackPatch"
# 输出写到 _tools\IlDump\bin\Debug\net9.0\il_out.txt，能看到对应的 "===== 类型::方法 =====" 就是编进去了

# b) pck 里有没有新图（有加图片时）
python _tools\pck_list.py dist\Subaru\Subaru.pck | Select-String 'vincent_power'

# c) 旧的、已删的资源还在不在 pck 里（在的话说明要重新打包）
python _tools\pck_list.py dist\Subaru\Subaru.pck | Select-String 'mana_purge'
```

> ⚠️ **改了图集/贴图内容时，pck 体积可能完全不变**（2026-11-20 实测：`subaru_0.png` 从 732 KB 换成 897 KB 再换成 770 KB，pck 三次都是 102,870,668）。
> 原因是 VRAM 压缩后的贴图是**定长块**（2048² × 4bpp = 4,194,356 字节），内容变了长度不变。
> 所以**别用体积判断有没有生效**，要提出来比 md5：
>
> ```powershell
> # 源工程里刚重新导入的贴图
> (Get-FileHash "src\Subaru\.godot\imported\subaru_0.png-*.bptc.ctex" -Algorithm MD5).Hash
> # pck 里的那一份（pck_get 的偏移略偏几字节，但同一份代码两次提取仍然可比较）
> python _tools\pck_get.py dist\Subaru\Subaru.pck "subaru_0.png" "_tools\tmp\pck_ctex.bin"
> (Get-FileHash "_tools\tmp\pck_ctex.bin" -Algorithm MD5).Hash
> ```
>
> 更省事的判据：`src\Subaru\.godot\imported\subaru_0.png-*.bptc.ctex` 的**修改时间**应该晚于你替换 PNG 的时间、早于 pck 的时间；两者对得上就是新的。
> 换贴图前务必先跑一次 `MegaDot --headless --path src\Subaru --import`，否则 publish 用的是 .godot 里的旧 .ctex。

### 5. 测试 + 读日志

重启游戏，然后：

```powershell
$log = "$env:APPDATA\SlayTheSpire2\logs\godot.log"
Select-String -Path $log -Pattern '\[Subaru\]|\[DEBUG\]|ERROR|Exception' |
  Where-Object { $_.Line.Length -lt 300 } | Select-Object -Last 25
```

要看的几行：

| 日志 | 含义 |
|---|---|
| `[Subaru] patch classes applied=NN, skipped=0` | 补丁全部挂上；**skipped > 0 就是有补丁目标对不上**，去 `ApplyPatchesIndividually` 的日志里找是哪一个 |
| `[Subaru] [ContentPack] Applied N deferred registration step(s); 0 failed` | 内容注册正常 |
| `[Subaru][DEBUG] ...` | 只有打了临时调试补丁时才会出现（如 `encounter forced -> CeremonialBeastBoss`），用来确认补丁真的挂上了 |
| `[ERROR] Encountered error on game startup!` | 启动失败，下面几行就是根因 |
| `[ERROR] ... TypeLoadException` / `MissingMethodException` | 换了游戏版本后最常见的两种，基本都是 API 变了 |

游戏内验证走一遍真实操作（进战斗、打一张牌、触发一次死归），别只看日志就下结论。

### 6. 回滚

```powershell
# 用最近一次备份覆盖回去
Get-ChildItem _tools\mods_backup_* -Directory | Sort-Object LastWriteTime -Descending |
  Select-Object -First 1 | ForEach-Object {
    Copy-Item "$($_.FullName)\*" 'D:\SteamLibrary\steamapps\common\Slay the Spire 2\mods\Subaru' -Recurse -Force
  }
```

**整个 mod 起不来**时（不是某个功能坏了），先把 `mods\Subaru` 改名成 `Subaru.off` 再启动：

- 游戏能进 → 问题在我们的 mod，继续查
- 游戏还是崩 → 是别的 mod 或 BaseLib/RitsuLib 与当前游戏版本不兼容（拿这一条去排除很有效，2026-11-17 就是这么判定默认分支不是我们责任的）

### 7. 收尾（很容易忘）

1. **临时补丁不 bump 版本号、不传工坊** —— 但这也意味着**本地和工坊不一致**。验完把要留的改动整理好，下次发版一次带上
2. `release\workshop\Subaru\content\` 里要放**发布版**内容，不要把临时补丁的 dll 留在那儿（留着下次一上传就把没验证完的东西发出去了）
   - **现状（2026-11-24 23:12 起）**：content = **0.3.39 待审版**（已上传成功，但 Steam 判「此次提交正在等待服务人员批准」，审核通过前对外仍是 0.3.38；dll `F47D5D71…` / pck `E88BC0EE…`；上传日志 `release\workshop\Subaru\up039_1.txt`，状态见 `知识库\基准数字.md` §1.1）
   - ⚠️ content **不等于** dist 只是「本地装着未发版改动时」的情况：现在 dist == content == 安装目录（**0.3.39**）；下次改完代码又会分叉。发版第 4 步「拿 dist 三件覆盖 content」不能省，省了等于没改
   - 线上 0.3.2 的原样存档在 `_tools\baseline_online_0.3.2\`（dll / pck / json，取自 Steam 缓存）；要回到「很早那一版」用这份，其余版本按 `release\Subaru_v<版本>.zip` 归档回滚
3. 如果是「发布版恢复」：用 `_tools\mods_backup_*`（历史部署）或 `_tools\baseline_online_0.3.2\`（线上 0.3.2 原样）覆盖 `mods\Subaru`；

   **别拿 dist 当线上版**——dist 可能装着未发版改动
4. 记一笔：改了什么、怎么验的、结果如何（写进当天的 `docs\交接_<日期>.md`）

## 发布（上传工坊，2026-11-17 定版流程）

```powershell
# 1) bump 版本号（只改 src\Subaru\Subaru.json 的 version）
# 2) publish（动过 localization 必须 publish，见 §2 的 ⚠️）
# 3) 部署到本机
python _tools\deploy_mod.py
```

```powershell
# 4) 同步工坊 content：只放 dll / pck / json，绝对不要放 pdb
#    （0.3.3 曾经把 98 MB 的 pdb 传上去，file_size 99,167,396 → 修掉后 99,004,164）
Copy-Item dist\Subaru\Subaru.dll, dist\Subaru\Subaru.pck, dist\Subaru\Subaru.json `
  release\workshop\Subaru\content -Force
Remove-Item release\workshop\Subaru\content\Subaru.pdb -ErrorAction SilentlyContinue

# 5) 改 release\workshop\Subaru\workshop.json 的 changeNote（英文；中/日文另外给用户贴）
# 6) 上传（在这个目录里跑）
cd release\workshop\Subaru
.\ModUploader.exe upload -w .
```

**核验**（Steam Web API，不需要 key，但**本机需要走代理**；直连会 `WinError 10061`）：

```powershell
python -c "import urllib.request,urllib.parse,json;
d=urllib.parse.urlencode({'itemcount':1,'publishedfileids[0]':'3840131390'}).encode();
r=json.load(urllib.request.urlopen(urllib.request.Request('https://api.steampowered.com/ISteamRemoteStorage/GetPublishedFileDetails/v1/',data=d)));
f=r['response']['publishedfiledetails'][0];
print(f['file_size'], f['time_updated'], f['title'], f['visibility'])"
```

看三样：`file_size` 应等于 `dll + pck + json`；`time_updated` 是刚才；`preview` 仍是 **661×661** 方图。
**跑不通（代理没开）时的判据**：`mod-uploader.log` 末尾的 `Successfully uploaded '' to the workshop with id …` + 进程 exit 0。
`k_EItemUpdateStatusInvalid` 是上传流程收尾时固定出现的状态值，**不是错误**（0.3.25 / 0.3.26 / 0.3.27 都有），别被它骗。

**分发打包**（可重复用，别手工复制目录）：

```powershell
python _tools\pack_release.py
```

从 `dist\Subaru\Subaru.json` 读版本号，生成 `release\Subaru_v<版本>\`（含 `安装说明.txt` + `mods\Subaru\`）和同名 zip。
安装说明默认复制上一个版本目录里的那份。0.3.27 实测：zip 91.8 MB（96,237,653 B），条目只有 mod 三个文件 + 安装说明。
