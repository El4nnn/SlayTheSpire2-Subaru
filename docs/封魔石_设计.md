# 封魔石 · 设计稿（已实装 0.2.62）

> 📌 **active** ｜ 最后核对：2026-11-23 ｜ 已实装（0.2.62）

2026-11-16 定稿。旧稿「消除该敌人所有增益 + 27 条黑白名单」整条作废。

## 1. 卡面

| 项 | 值 |
|---|---|
| 名称 | 封魔石 / Sealing Stone |
| 费用 | 3（升级：2） |
| 类型 | 技能 |
| 稀有度 | 稀有 |
| 目标 | 任意敌人 |
| 词条 | [阴魔法]、[消耗] |
| 效果 | 该敌人永久失去「本场打出过的[阴魔法]张数」层[力量]（每张 **1** 层） |
| 升级 | 只减费，不改数值 |

卡面文字里的数字用 `SealCountVar` 动态渲染，每次渲染重新取当前计数，
所以战斗中看到的永远是「这一刻会削多少层」。

## 2. 结算口径

- **计数器**：本场战斗累计打出过的[阴魔法]牌张数，含自动打出的（如「机遇门」带出来的）。
- **不含本张**：记账挂在 `SubaruCard.OnPlay` 里 `OnPlayCard` **之后**（`YinLedger.MarkPlayed`），
  封魔石自己那一张要到下一次结算才计入。
- **挂官方 debuff**：直接 `PowerCmd.Apply<StrengthPower>(target, -count, ...)`，与「星蚀」同一套写法；
  **不额外挂记账能力**，敌人状态栏只有一个「力量 ↓」图标。
  食精灵者那种隐藏记账能力（`IsVisibleInternal => false`）只有「临时削减要到期还原」时才需要，这里不需要。
- **允许削到负数**：官方力量本来就允许负值，削成负数等于给敌人上虚弱，这是本牌强度核心。
- **随死归回溯**：计数器跟着快照走——`DeathReturnSpike` 在存档点记下 `_yinInSnapshot`，
  回档时 `YinLedger.SetCount` 退回去（和「造成过伤害次数」同一套做法）。
  力量削减本身也跟随战斗状态，两者口径一致：回档 = 这张牌没打过。
- **清零**：战斗结束由 `DeathReturnSpike.ResetForCombat` 一起清零。
- **不挂[腐蚀]**：已带[消耗]，一场一次。

## 3. 联动

- **贝蒂**：阴魔法首张 −1 费 → 3 费变 2 费。
- **机遇门**：可以从抽牌堆顶免费打出来，是天然搭档。
- **食精灵者（本回合全体 −3）/ 星蚀（偷力量）**：可以叠加，构成「把敌人力量削成负数」的路线。
- **成长型 BOSS**：这是它最赚的用法——BOSS 攒到 10 层力量时一张能抵掉一大截。

## 4. 平衡与风险

1. **数值**：一场战斗通常打出 3~6 张阴魔法 → 削 3~6 层。若手感过强，把 `OnPlayCard` 里的
   `count` 乘一个系数即可（一行）。
2. **与未来的「每打出 N 张阴魔法」收益牌**：会互相放大，新增时要一起看。
3. **力量归零后的观感**：敌人力量被削成负数时伤害数字会很低，确认 UI 表现不像 bug。
4. **测试点**：
   - 目标有力量 / 无力量两种情况；
   - 削到负数后的伤害结算；
   - 与机遇门自动打出的组合；
   - 死归后计数器是否退回（日志 `yin counter restore: A -> B`）。

## 5. 顺带核查：星蚀的状态图标

结论：**没有「挂两个状态」的问题**，不需要改。

依据（`MoreCards.cs:109-148`）：星蚀只给敌人 `StrengthPower(-2)`/`DexterityPower(-2)`、
给自己 `StrengthPower(+2)`/`DexterityPower(+2)`，全程只有官方力量/敏捷，没有隐藏记账能力。

「两个状态」的成因是食精灵者的**临时削减**：它必须再挂一个 `TempEnemyStrengthDownPower`
在敌人回合结束时把力量补回去，而这个记账能力本身也占一个状态栏图标，
所以敌人身上会同时出现「力量 −3」和「力量削减 3」。
修法是 `IsVisibleInternal => false`（`TempEnemyStrengthDownPower.cs:37`），
记录见 `docs\更新汇总_0.1.0-0.2.35.md`「食精灵者显示多余的『力量削减』图标」。

封魔石是永久削减，没有第二层记账，不会重蹈这个问题。
