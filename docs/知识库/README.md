## 1. 五层模型（先分清「哪一层」，再找文件）

| 层 | 是什么 | 时效承诺 | 在哪 |
|---|---|---|---|
| **L0 入口** | 一张表跳转全部文档 | 必须最新 | 本文 + `docs\索引_文档与笔记.md` |
| **L1 权威 canon** | 每主题**唯一**的现状事实与硬规则 | **强**：与代码同源，改动当天更新 | `docs\知识库\基准数字.md`、`docs\构建与部署.md`、`docs\cutin_工作流.md`、`docs\角色动画_图集约束.md`、`docs\状态与关键词.md` |
| **L2 根因库** | 「现象 → 根因 → 定论」条目，按日期累积 | **强**：单条永久有效，可被新条目取代 | `docs\交接_技术问题_<日期>.md` |
| **L3 过程记录** | 某天做了什么、为什么、发了哪版 | **弱**：写完即历史，只作追溯 | `docs\交接_<日期>_<主题>.md` |
| **L4 参考** | 设定 / 文案 / 美术规格 / 旧规划 | **无**：只作参考，数字不作判据 | `docs\菜月昴_能力设定.md`、`文案清单.md`、`流程说明.md` 等 |
| 旁路 **notes** | 3–5 KB 速查（会被注入上下文） | 中 | 笔记系统（id 见 §5） |
| 旁路 **release** | 发版文案与工坊物料 | 强（与线上同源） | `release\workshop\Subaru\` |

**一句话原则**：**L1 管事实、L2 管原因、L3 管历史、L4 只供参考**。
任何数字与现状，先看 L1；L1 没有，才去 L2/L3 找，并当场核对代码。

## 2. 目录一览

```
docs\

├── 知识库\                      # ← 本目录：结构与规则，不放专题内容

│   ├── 基准数字.md              # L1：版本 / 指纹 / 计数 / 机制数值（唯一来源）
│   ├── 登记表.md                # 全量文档登记：类型 / 状态 / 替代关系 / 最后核对
│   ├── 规范_修改与记录.md        # 规则本体（改什么、怎么写、怎么归档）
│   └── 模板.md                  # 六套可直接抄的模板
├── 交接_技术问题_2026-11-2x.md  # L2 根因库（按日期）
├── 交接_2026-11-2x_<主题>.md    # L3 过程记录
├── cutin_工作流.md             # L1 演出/立绘操作手册
├── 构建与部署.md               # L1 构建、部署、发版
└── 其他 *.md                   # L4 参考（状态见 登记表.md）
```

## 4. 可信度阶梯（冲突时按此裁决）

1. **代码 / IL**（`src\Subaru\SubaruCode`、`IlDump` 反编译）
2. **`基准数字.md`**（每条都写了核对命令与日期）
3. **L2 根因库条目**（各自带证据）
4. **L1 其他文档**
5. **L3 过程记录**（只证明「当时是那样」）
6. **L4 参考 / 旧规划**（数字不可引用）

冲突处理的动作见 `规范_修改与记录.md` §7：**先分类（版本漂移 or 真 bug）→ 以代码定死 → 旧文档加勘误块 → 登记表记一笔**。

## 6. 维护节奏

| 时机 | 必须做的事 |
|---|---|
| 结论落地当天 | L2 新增/更新一条 + 笔记同步 + `登记表.md` 状态 |
| 发版 | `基准数字.md` 指纹与版本、`索引` §4、当日交接、登记表 |
| 推翻旧结论 | 旧文档加**勘误块**（不改原文），`登记表.md` 标 `superseded` 并指向替代者 |
| 每月（或每 3 个版本） | 扫一遍 `登记表.md`，把「部分过期」的收敛成勘误或归档 |
